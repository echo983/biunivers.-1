# 浏览器云端个人桌面 V0.11 Wormhole 规范评审

状态：评审通过

日期：2026-07-30

## 1. 必要性

结论：必要，但必须限定为按需文件通道。

浏览器上传、单文件下载和目录 ZIP 已经覆盖偶发交换，但无法满足远程目录挂载和用户主动批量
同步。WebDAV 复用 HTTPS，Windows/macOS 有原生入口，Linux/macOS 可使用 rclone；与新增
SMB/SFTP 或开发专用客户端相比，它是当前跨主流 PC 系统的最小共同入口。

Wormhole 需要完整目录读写，因此不能作为普通第三方应用。编译期 internal 应用加宿主协议
适配层是必要的最小特权扩展。

## 2. 保留项

以下能力具有直接需求，保留：

- 可开关；
- 开启时随机 10 位密码；
- WebDAV 读写；
- Windows Explorer 和 macOS Finder 基本访问；
- rclone mount；
- 方向明确、用户主动的 rclone sync；
- PROPFIND、GET/HEAD/Range、PUT、MKCOL、MOVE、COPY、DELETE；
- 基本 LOCK/UNLOCK；
- 流式大文件；
- PVLog 原子事务与冲突保护；
- HTTPS 警告、失败限速和立即撤销；
- 明确显示“不是实时同步”。

## 3. 删除或延期项

以下能力第一版必要性低，删除：

- 设备列表、配对二维码和在线状态；
- 每设备独立密码；
- 长期 token、OAuth 和客户端证书；
- 实时同步守护进程；
- rclone bisync；
- 后台任务调度；
- 版本冲突 UI；
- 共享链接；
- 多用户 ACL；
- 带宽图表、审计日志和活动历史；
- 自动过滤 `.DS_Store` 等文件；
- ZIP64、服务端压缩或转码；
- 自动安装 rclone/FUSE；
- 完整 WebDAV dead property 数据库；
- Office 协同编辑承诺。

## 4. 关键决策

### 4.1 状态不持久化

Wormhole 重启即关闭，凭据只在内存存在。

这是安全和实现复杂度之间最好的边界：

- 无需保存或加密可回显密码；
- 宿主重启天然撤销；
- 符合短期开启的 Wormhole 概念；
- 不妨碍用户在一次传输或同步期间持续使用。

### 4.2 固定用户，临时密码

单用户产品不需要账号管理。固定用户名加随机临时密码足够。密码必须通过 HTTPS 使用，关闭或
轮换立即失效。

### 4.3 主推 rclone，原生客户端为便利入口

Windows Explorer 和 Finder 提供免安装体验，但客户端各有历史限制。大文件、可控缓存和批量
同步主推 rclone，不把系统原生入口描述为完全一致的 POSIX 文件系统。

### 4.4 Sync 不是后台功能

Wormhole 只提供 WebDAV。同步动作由用户主动运行 rclone，必须选择方向并看到删除警告。

### 4.5 不修改第三方协议

Wormhole 不改变 Static App、Open Resource、Resource Session 或 Host API。第三方应用仍不能
枚举文件树。

### 4.6 不建立第二套文件元数据

WebDAV 属性由 EntryIndex、Entry ID、mtime、size 和 Content FID 投影。除临时锁外不维护
WebDAV 专用数据库。

## 5. 风险审查

| 风险 | 结论 |
|---|---|
| Basic 密码泄漏 | 仅 HTTPS、临时凭据、可立即撤销、失败限速 |
| 10 位密码过短 | 约 58 bit 随机强度，适合短期个人通道；不作为长期公网密码 |
| 大文件耗尽内存 | PUT/GET 均流式，限制并发与最大文件 |
| WebDAV 客户端覆盖新内容 | old FID、If、锁和 CAS 共同保护 |
| Windows 大文件失败 | 明示原生 WebClient 限制，大文件主推 rclone |
| 平台大小写差异 | Wormhole 写入口拒绝新大小写冲突，既有冲突提示 |
| disable 时半成品 | abort 流且不发布 Ref；不可达对象留待 GC |
| WebDAV XML 攻击 | 64 KiB、禁 DTD/外部实体、严格转义 |
| 路径穿越 | 单次解码、分段校验、固定 root、Destination 不联网 |
| internal 特权膨胀 | 仅新增一个静态映射应用，不开放动态 internal |

## 6. 闭环结论

设计已经覆盖：

- 开启、显示、使用、轮换、关闭和重启；
- Windows/macOS 原生连接；
- Linux/macOS rclone mount 与主动 sync；
- 文件系统读取、写入、目录和原子重命名；
- 大文件、Range、mtime、空目录；
- 并发、锁、CAS 和条件请求；
- HTTPS、认证限速、路径/XML 安全；
- File Service offline 与中途关闭；
- 第三方权限不扩张。

剩余不确定性主要来自不同 WebDAV 客户端的具体兼容行为，应通过施工中的协议测试和真实
Windows/macOS/rclone 验收解决，不需要再扩大第一版规范。设计具备施工条件。
