# 浏览器云端个人桌面 V0.4 文件管理器施工计划

状态：施工中（阶段 3 已完成）

目标：交付基础可用的 internal 文件管理器，不扩大到文件关联和完整历史产品。

## 阶段 0：设计基线

- [x] 明确 internal 权限边界；
- [x] 复用现有句柄与传输能力；
- [x] 定义目录 mutation API；
- [x] 强制 expected revision 冲突保护；
- [x] 明确移除不等于对象物理删除；
- [x] 排除 Resource Exchange、打开方式和历史 UI。

出口：需求、技术设计和施工计划通过评审并提交。

## 阶段 1：internal 注册与实例

- [x] 注册 `system.files` 默认应用和图标；
- [x] 加入客户端与服务端 reserved ID；
- [x] `AppRenderer` 接入文件管理器占位状态；
- [x] internal 文件实例 bootstrap 与卸载撤销；
- [x] File Service disabled/offline 降级界面；
- [x] 覆盖配置冲突和实例权限测试。

出口：文件应用可打开，只有编译期 `system.files` 能取得 internal 文件实例。

## 阶段 2：目录管理服务

- [x] 统一 Entry 名称校验；
- [x] 实现 `InternalFileManagerService`；
- [x] 新建目录；
- [x] 重命名与移动；
- [x] 递归/非递归移除；
- [x] 根保护、重名、循环和 stale revision；
- [x] internal HTTP 路由与结构化错误。

出口：服务端所有目录 mutation 具备事务测试，第三方 Origin 和错误 appId 被拒绝。

- [x] 目录列表、排序、选择和空状态；

出口：不依赖上传下载即可完成目录树管理闭环。

## 阶段 4：上传与下载

- [ ] internal transfer 的精确 Desktop Origin 支持；
- [ ] 本机文件上传；

出口：真实文件可从浏览器进入 File Service，并能完整下载校验。

## 阶段 5：验收与归档

- [ ] 全量测试、lint、Rust/WASM 向量和生产构建；
- [ ] Docker + 真实 R2 人工验收；
- [ ] 新建、重命名、移动、移除、上传、下载；
- [ ] stale revision 冲突；
- [ ] 容器重启恢复；
- [ ] 只读 GC 确认移除对象不被错误物理删除；
- [ ] 更新 README、文档索引和版本归档。

出口：V0.4 闭环通过，后续历史与 Resource Exchange 保持独立范围。

## 合并门槛

- 需求范围没有隐式扩大；
- internal 权限不能由第三方获取；
- 所有 mutation 都经过 File Service 和 Ref CAS；
- 失败或冲突不改变旧版本；
- 文件内容不进入控制面 JSON；
- 不存在 GC 删除路径；
- 文档、实现和验收一致。
