# BWA 启动失败报告

状态：已实现的最小生命周期约定

## 目标

当 Workspace Application Instance 无法完成启动时，由 Workspace Application Manager
统一保存并呈现可操作的原因。该机制不声明或探测应用依赖，也不增加业务健康状态协议。

## 启动成功边界

Manager 的“启动”操作包含：创建 Run、启动容器、等待 `GET /health` 返回 `2xx`。只有三步
全部完成，操作才成功。容器提前退出或 30 秒内未就绪均属于启动失败。

正常完成清理时，失败 Run 的 COW Upper 自动丢弃，不要求用户处置尚未成为可用状态的启动副作用；如果清理本身失败，则保留失败 Run 供恢复。失败记录与
Run 一起保留，用户修改配置后可以直接重试。

## 应用输出约定

应用已知无法启动时，应向标准错误输出一行：

```text
BWA_STARTUP_ERROR: <不含 secret、面向用户且可采取行动的简短说明>
```

Manager 取日志中最后一条该前缀作为摘要，最长 512 个字符。没有规范摘要时使用宿主生成的
通用说明。该前缀是可选增强；旧应用无需修改也能得到退出码和受限日志尾部。

## 保存与呈现

每个失败 Run 最多保存一条记录：失败阶段、退出码、摘要、最多 16 KiB 日志尾部和失败时间。
界面直接显示摘要、阶段和退出码，日志按需展开。日志进入持久层前移除控制字符，并对常见
Bearer、token、password、secret 与 API key 形式做保守遮蔽；应用仍负有不输出 secret 的
基本责任。

第一版阶段仅有：准备镜像、准备运行环境、启动应用、等待应用就绪。Manager 不理解应用的
依赖类型，不自动修复、重试或建立错误码注册表。
