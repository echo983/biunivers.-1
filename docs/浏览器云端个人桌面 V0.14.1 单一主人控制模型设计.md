# Biunivers V0.14.1 单一主人控制模型设计

状态：现行设计  
上位原则：`个人计算机软件边界的组织化偿还模型.txt`

## 1. 决策

Biunivers 是单一自然人直接使用的个人计算机环境。系统不再把这位主人拆成“普通用户”和“管理员”两个身份，也不再要求主人为应用管理、Workspace Application 管理或 File Service 运维重复输入管理员 token。

“我正在操作可信桌面”就是控制面的交互事实。权限约束继续施加在软件执行者、对象、动作、范围和时间上，而不是施加在主人身上。

## 2. 边界

- 整个 Desktop Origin 必须由部署边界保护；需要公网访问时，由 Cloudflare Access、反向代理认证或 VPN 等入口设施确认访问者。
- `/api/v1/control/*` 只接受浏览器从配置的 Desktop Origin 发起的同源请求。写操作必须携带精确的 `Origin`，全部请求必须为 `Sec-Fetch-Site: same-origin`。
- 第三方静态应用继续运行在独立 App Origin；BWA 界面继续通过受控代理隔离。它们不能直接调用控制面。
- 第三方应用的文件访问仍由文件能力、Open Resource 和 Resource Session 约束。本次改动不增加任何文件遍历或系统管理权限。
- Compute Runtime 的宿主间认证、Wormhole 密码、S3 凭据和应用 secret 都是不同边界，不属于被删除的“主人管理员密码”。

同源校验是浏览器程序边界和 CSRF 防线，不是远程用户认证。能直接访问宿主网络并伪造 HTTP 请求的进程已经处于部署信任边界内，因此部署者仍须限制主机和端口暴露。

## 3. API 与体验

- 管理接口由 `/api/v1/admin/*` 迁移为 `/api/v1/control/*`。
- 删除 `BIUNIVERS_ADMIN_TOKEN`、Bearer 校验和所有管理员密码输入、锁定界面。
- 应用管理和 Workspace Application Manager 打开后直接加载；失败时呈现真实的连接或服务状态错误。
- 备份与 GC 等运维动作保留为控制操作，不变成第三方可调用的公共 Host API。

## 4. 闭环判断

主人通过受保护的桌面入口进入系统；可信桌面能够管理系统；不可信应用只能持有明确授予且可撤销的能力；后台执行器仍受 Workspace、Run、租约和沙箱约束。身份入口、控制面、应用隔离和资源能力四层各自承担单一职责，因此第一版闭环，不需要再造本机管理员账户、角色系统或会话登录服务。

## 5. 暂不实现

- 多用户、组织、角色与 RBAC；
- 桌面内部再次登录、锁屏认证或 sudo 式提权；
- 以同源校验替代公网入口认证；
- 对所有本机恶意进程作强对抗承诺；
- 控制操作审批流和复杂审计系统。

若未来引入多自然人共享同一部署，再单独设计身份与委托模型，不在单一主人模型上预埋空泛角色。
