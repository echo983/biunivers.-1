# 浏览器云端个人桌面 V0.10 目录 ZIP 导出施工计划

状态：待施工

日期：2026-07-30

## 阶段 1：ZIP Store 核心

- 实现独立的流式 ZIP32 Store Writer；
- 增量 CRC-32、UTF-8 路径、空目录、Data Descriptor 和 Central Directory；
- 实现准确总尺寸预估、ZIP32 上限和路径安全检查；
- 单元测试空归档、文件、目录、Unicode、CRC、确定性输出及全部超限边界。

出口：生成物可被标准 ZIP 工具完整校验和解包，正文不被完整缓存在服务端。

## 阶段 2：快照导出服务

- 在 internal 文件管理服务中增加导出计划；
- 一次加载 EntryIndex，校验 revision，规范化选择并递归展开目录；
- 固定路径、mtime、尺寸与不可变 Content Ref；
- 限制 10,000 个条目并在响应开始前完成所有结构校验；
- 从 `FileContentStore.readChunks()` 流式提供正文；
- 覆盖并发重命名、移动、删除、内容更新后的快照一致性测试。

出口：目录结构和文件内容来自同一开始快照，导出不写 RefStore 或 S3。

## 阶段 3：HTTP 流与取消

- 增加 `POST /api/v1/internal/files/exports/zip`；
- 仅允许 `system.files` 实例；
- 设置安全文件名、Content-Type、Content-Length 和 no-store；
- 实现 Node 响应背压与请求中止传播；
- 在写头前返回结构化校验错误，写头后失败则终止不完整响应；
- 增加路由鉴权、revision 冲突、Content-Disposition、长度和断连测试。

出口：真实 HTTP 下载能够稳定流式读取，错误和取消不会伪装成成功。

## 阶段 4：文件管理器集成

- 下载按钮支持单文件、单目录和多选三种行为；
- 单文件继续沿用现有传输路径；
- 目录或多选调用 ZIP 导出接口；
- 按选择动态更新按钮说明；
- 复用进度、取消、错误提示和成功提示；
- 仅在完整响应后创建 Blob URL 并触发保存。

出口：不新增工具栏按钮，用户可直接从现有下载入口导出目录或批量项目。

## 阶段 5：回归与真实验收

- 自动测试、ESLint、TypeScript、生产构建和 Docker 镜像通过；
- 使用真实 R2 验证空目录、嵌套目录、Unicode 名称、小文件和大于 64 MiB 文件；
- 使用系统 ZIP 工具解包并校验文件内容；
- 验证下载进度、取消、并发变更快照及浏览器不保存失败归档；
- 回归原文件下载、上传与文件管理器批量操作；
- 更新关于页面、文档索引和验收记录，完成后将本计划标记归档。

出口：真实环境验收通过，相关文档同步，具备合并条件。

## 实施顺序

严格按“ZIP 核心 → 快照服务 → HTTP → UI → 验收”推进。不要先在 React 中递归调用目录
列表接口，也不要为了导出功能修改第三方协议。
