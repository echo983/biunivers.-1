# 浏览器云端个人桌面 V0.7 桌面表面需求方案

状态：设计基线

前置版本：`v0.6.0` 加窗口点击激活修复

架构决策：[ADR-0003](decisions/0003-桌面表面使用稳定引用表.md)

## 1. 目标

V0.7 把当前“自动显示应用”的图标层升级为可管理 Desktop Surface。桌面可以保存应用、文件
和目录的稳定引用，用户可以框选、多选和成组拖动图标位置。

框选与多项目拖动是第一版完成条件，不作为低优先级视觉增强。没有这些操作，桌面即使能保存
引用，也仍然不像一个完整可用的桌面环境。

## 2. 第一版用户闭环

用户可以：

1. 从 App 菜单或应用管理把应用添加到桌面；
2. 从文件管理器把选中的文件或目录添加到桌面；
3. 双击应用启动应用；
4. 双击文件进入既有 Open Resource 流程；
5. 双击目录打开或聚焦文件管理器并进入该目录；
6. 单击选择一个图标；
7. 按住 Ctrl/Cmd 切换单个项目是否入选，按住 Shift 把项目加入选择；
8. 从桌面空白区域按下左键并拖动选择框；
9. 拖动一个已选图标时，全部选中图标保持相对位置一起移动；
10. 从桌面移除一个或多个引用，而不改变目标对象；
11. 在桌面区域使用宿主自制右键菜单；
12. 刷新、换标签页或重启容器后恢复引用和布局。

## 3. 引用语义

第一版只接受宿主内建类型：

```ts
type DesktopTarget =
  | { type: "app"; handle: string }
  | { type: "file"; handle: string }
  | { type: "directory"; handle: string };
```

`handle` 是稳定定位值，不是权限：

- app handle 为稳定 `appId`；
- file/directory handle 为稳定 `Entry ID`；
- 桌面不保存路径、FID、S3 Key、Ref、instance token 或 file capability。

同一目标不重复添加。应用卸载或 Entry 移除后项目显示失效状态，不自动从桌面消失。

## 4. 选择状态机

选择只存在于当前页面内存，不持久化。

### 单击

- 无修饰键点击未选项目：只选择该项目；
- Ctrl/Cmd 点击：切换该项目；
- Shift 点击：把该项目加入当前选择；
- 点击空白：清空选择；
- Escape：清空选择；
- Ctrl/Cmd+A：选择当前桌面全部有效和失效项目。

无修饰键按下一个已处于多选集合中的项目时，暂时保留集合，以便开始成组拖动。如果直到
pointerup 都没有越过拖动阈值，则选择收敛为该单个项目。

### 框选

- 只有主键在桌面空白处按下时才可能开始；
- 指针移动超过 4 CSS px 后显示选择框；
- 使用 Pointer Events 和 pointer capture，不使用 HTML5 Drag and Drop；
- 选择框与图标完整 hitbox 相交即选中；
- 无修饰键时实时替换选择；
- Ctrl/Cmd 时以 pointerdown 时的选择快照为基线，切换框内项目；
- Shift 时以快照为基线，加入框内项目；
- pointerup、pointercancel、窗口失焦或 Escape 都必须结束框选并释放 capture；
- 选择框只存在于图标层，不能穿过任务栏、菜单或窗口捕获输入。
- 被窗口遮挡的桌面区域不能响应框选起点、图标点击或拖动；窗口仍是该区域最上层的输入目标。

短距离移动仍视为空白点击，不能产生闪烁的选择框。

## 5. 拖动与布局

图标使用逻辑网格位置：

```ts
interface DesktopPosition {
  column: number;
  row: number;
}
```

交互规则：

- 在未选项目上开始拖动时，先把选择替换为该项目；
- 在已选项目上开始拖动时，拖动整个选择集合；
- 移动超过 4 CSS px 后才进入拖动；
- 拖动预览用 CSS transform，不在每个 pointermove 写服务端；
- 全组选中项目使用相同网格 delta，保持相对形状；
- pointerup 时一次提交全部新位置；
- 如果目标与未选项目冲突，寻找距离目标最近、能容纳整组的网格平移；
- 避让只能改变整组的共同 delta，不能重排、压缩或拆散组内图标；
- 找不到合法位置或 revision 冲突时整组回到原位；
- 服务端必须原子接受或拒绝整组位置，不能只移动其中一部分；
- 小视口可以临时投影到可见网格，不静默覆盖规范位置。

## 6. 视觉与可访问性

- 选中项目有明确底色和边框；
- 选择框使用半透明填充与高对比边框；
- 多项目拖动显示选中数量和整体预览，不克隆完整 DOM；
- 失效应用、文件或目录显示统一警告状态和原因；
- 桌面项目继续使用可聚焦 button；
- `aria-selected` 与视觉选择一致；
- 箭头键在网格中移动焦点，Enter 打开，Space 切换选择；
- 拖动不能触发浏览器文字选择或图片原生拖动。

## 7. 删除与危险操作

键盘 Delete 或菜单“从桌面移除”只删除 DesktopItem。文案必须使用“从桌面移除”，不能写
“删除文件”或“卸载应用”。

实际文件移除和应用卸载仍只能在文件管理器或应用管理中执行。

## 8. 桌面右键菜单

- 仅在真正的桌面表面内拦截 `contextmenu`，包括桌面空白和桌面图标；
- 窗口、iframe、任务栏、开始菜单及其他浮层继续使用各自的右键行为，桌面不能截获；
- 菜单出现在指针附近，并限制在桌面可见边界内；
- 点击菜单外、按 Escape、窗口失焦或开始其他桌面操作时关闭；
- 第一版菜单只有一个启用的“刷新”项目；
- “刷新”可以点击，点击后只关闭菜单，不重新加载页面、不重新请求数据，也不改变选择和布局；
- “刷新”的无操作语义是有意保留的桌面文化梗，不应被实现者改成真实刷新。

## 9. 不包含

- 动态视图具体格式；
- 第三方自定义 Resolver；
- 多桌面和工作区；
- 文件夹内联展开；
- 自由像素定位和图标重叠；
- 框选窗口；
- 桌面文件拖入第三方 iframe；
- 外部系统文件拖放到桌面；
- 多用户共享布局；
- 触屏框选手势。

## 10. 验收条件

- 应用、文件和目录引用完成添加、解析、打开和移除闭环；
- 文件重命名或移动后桌面入口仍有效；
- 应用停用/卸载和 Entry 移除显示失效状态；
- 框选的替换、追加、切换和取消路径通过；
- 单个和多个图标拖动、吸附、碰撞、回退通过；
- 快速点击、双击和拖动不会互相误判；
- 两个标签页 revision 冲突不覆盖布局；
- 容器重启后引用和布局恢复；
- 桌面空白和图标区域显示自制右键菜单，“刷新”可点击且没有副作用；
- 窗口、iframe、任务栏和其他浮层的右键事件不被桌面截获；
- 桌面引用不会被当作 capability；
- lint、测试、构建和真实浏览器验收通过。
