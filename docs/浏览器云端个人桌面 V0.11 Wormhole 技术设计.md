# 浏览器云端个人桌面 V0.11 Wormhole 技术设计

状态：设计基线

日期：2026-07-30

## 1. 总体结构

```text
Windows Explorer / Finder / rclone
                  │
          HTTPS + WebDAV Basic Auth
                  │
      /wormhole/webdav/ 路由与协议层
                  │
       WormholeFileServiceAdapter
                  │
 EntryIndex + FileContentStore + FileSystemTransactions
                  │
        本地 RefStore + S3 不可变对象
```

Wormhole 不启动第二套文件服务器，不把 S3 bucket 暴露给客户端，也不调用面向第三方应用的
Host API。它是与文件管理器并列的系统级适配层。

## 2. 组件

### `WormholeRuntime`

进程内保存：

- `enabled`；
- 当前用户名与密码；
- credential generation；
- 开启时间；
- 活动请求 AbortController；
- Basic Auth 失败限速状态；
- WebDAV 临时锁。

公开操作：

- `enable()`；
- `rotate()`；
- `disable()`；
- `status()`；
- `authenticate()`；
- `registerRequest()`。

`disable()`、`rotate()` 和服务关闭会：

1. 增加 credential generation；
2. 撤销旧凭据；
3. abort 活动请求；
4. 清空 WebDAV 锁；
5. 清除密码内存。

轮换随后生成一套新凭据并保持开启。

### `WormholeWebDavService`

负责：

- 规范化 WebDAV path；
- 加载 EntryIndex；
- 把路径解析为 Entry ID；
- 生成 PROPFIND 属性；
- 流式读写内容；
- 校验条件请求和锁；
- 调用 FileSystemTransactions 发布原子变更。

它不负责 HTTP Basic 解析、速率限制和 XML/HTTP 输出。

### `WormholeRouter`

负责：

- `/wormhole/webdav/` 下的 WebDAV 方法；
- Basic Auth challenge；
- 请求体与响应体流；
- Depth、Destination、Overwrite、If、Range 等 HTTP 头；
- XML 请求上限与响应；
- HTTP 状态映射；
- 背压、断连和 AbortSignal。

路由必须在静态站点 fallback 之前注册。PUT 使用原始请求流；XML 方法正文限制为 64 KiB，
禁止 DTD 和外部实体。

### `WormholeApp`

编译期 internal React 应用。通过同源 internal 控制 API 管理 Wormhole，不直接接触
repository、RefStore 或 S3。

## 3. Internal 控制 API

Wormhole 应用创建 `system.wormhole` 窗口实例 token。控制 API 必须：

- 来自 Desktop Origin；
- 使用 `Biunivers-Instance`；
- token 对应 `system.wormhole`；
- File Service ready。

接口：

```http
GET /api/v1/internal/wormhole
POST /api/v1/internal/wormhole/enable
POST /api/v1/internal/wormhole/rotate
DELETE /api/v1/internal/wormhole
```

状态响应：

```json
{
  "enabled": true,
  "username": "biunivers",
  "password": "Ab3...10",
  "path": "/wormhole/webdav/",
  "enabledAt": "2026-07-30T12:00:00.000Z"
}
```

关闭时不返回 credential 字段。响应统一 `Cache-Control: no-store`。密码不得进入异常详情、
埋点或访问日志。

开启和轮换是幂等边界：

- 已开启时再次 enable 返回当前状态，不偷偷换密码；
- rotate 只在已开启时成功；
- disable 已关闭实例仍返回关闭状态。

## 4. WebDAV 认证

使用：

```http
Authorization: Basic base64("biunivers:<password>")
```

未认证返回：

```http
401 Unauthorized
WWW-Authenticate: Basic realm="Biunivers Wormhole", charset="UTF-8"
Cache-Control: no-store
```

要求：

- 常量时间比较用户名与密码；
- 只接受一个 Authorization 值和合法 Base64；
- 密码为 ASCII，避免客户端 Basic 编码差异；
- 当 `Sec-Fetch-Site: cross-site` 时直接拒绝，非浏览器 WebDAV 客户端通常不发送该头；
- 不设置 CORS；
- 认证失败按来源地址做小型、有限容量的滑动窗口限速；
- 响应不区分“关闭”“用户名错误”“密码错误”。

建议限制：同一来源 60 秒内最多 10 次失败，记录最多 1024 个来源；成功认证清除该来源失败
记录。来源地址仅用于内存限速，不持久化。

## 5. 路径模型

WebDAV 根 `/wormhole/webdav/` 映射 File Service root Entry。

路径规则：

- 严格按 `/` 分段；
- 每段只解码一次；
- 拒绝编码的 `/`、`\`、NUL、控制字符、空段、`.`、`..`；
- 解码后要求 NFC；
- 复用 `validateEntryName`；
- 尾部 `/` 只表示 collection，不属于 Entry 名；
- 路径解析每个请求使用同一次 EntryIndex。

WebDAV 对外使用路径，但内部写操作尽早解析为稳定 Entry ID。MOVE 后 Entry ID 不变，COPY
分配新 Entry ID。

Windows 大小写不敏感，而 Biunivers 名称比较区分大小写：

- Wormhole 新建、移动和复制时拒绝同一目录下仅大小写不同的名称；
- 如果既有目录已经包含大小写冲突，PROPFIND 仍完整返回；
- UI 和文档提示该目录不适合 Windows Explorer，rclone 仍作为主兼容路径；
- V0.11 不全局改变 File Service 的名称语义。

## 6. WebDAV 方法

第一版方法矩阵：

| 方法 | 行为 | PVLog / 内容语义 |
|---|---|---|
| `OPTIONS` | 返回 DAV 能力和 Allow | 无写入 |
| `PROPFIND` | `Depth: 0` 或 `1` 枚举 | 单次 EntryIndex 快照 |
| `HEAD` | 文件元数据 | 无正文 |
| `GET` | 文件读取，支持单 Range | Chunk/Manifest 流 |
| `PUT` | 新建或替换文件 | 流式 put 后单次原子发布 |
| `MKCOL` | 新建空目录 | create-directory |
| `DELETE` | 删除文件或递归目录 | remove |
| `MOVE` | 重命名或移动 | move；覆盖时原子 batch |
| `COPY` | 复制文件或目录 | FID 复用；原子 batch |
| `LOCK` | 临时独占写锁 | 只写进程内锁表 |
| `UNLOCK` | 释放临时锁 | 不写 PVLog |
| `PROPPATCH` | 仅处理支持的 mtime | 必要时更新元数据 |

其他方法返回 `405 Method Not Allowed`。`PROPFIND Depth: infinity` 返回 `403`，避免一次请求
展开整棵文件树；rclone 自行递归 Depth 1。

## 7. 属性与响应

PROPFIND 至少提供：

- `displayname`；
- `resourcetype`；
- `getcontentlength`；
- `getcontenttype`；
- `getlastmodified`；
- `creationdate`；
- `getetag`；
- `supportedlock`；
- `lockdiscovery`。

文件 ETag：

```text
"<content-fid>"
```

目录 ETag：

```text
"dir-<entry-id>-r<revision>"
```

路径和 XML 文本必须转义。XML 响应使用 UTF-8。对请求的已知属性返回 `200 propstat`，未知属性
返回 `404 propstat`；空请求视为 `allprop`。

GET：

- `Accept-Ranges: bytes`；
- 支持一个 `bytes=start-end`；
- 返回 `206`、`Content-Range` 和准确长度；
- 多 Range 返回 `416`，不实现 multipart/byteranges；
- 完整 GET 直接使用 `readChunks()`；
- Range 使用 `readRange()`。

## 8. PUT 与修改时间

PUT 不把完整文件缓存到内存或本地临时文件：

1. 在开始读取正文前加载 Index，固定目标存在状态和旧 Content FID；
2. 流式写入 `FileContentStore.putStream()`；
3. 新文件使用 create-file；
4. 已有文件使用 expected old FID 的 set-file-content；
5. 如果目标在上传期间改变，发布失败并返回 `412 Precondition Failed`；
6. 冲突产生的不可达不可变内容由未来 GC 处理，不修改当前 Ref。

最大文件沿用 File Service 的 4 GiB 写入限制。已知 Content-Length 超限时在读取正文前返回
`413`；chunked upload 在越界时中止。

修改时间优先级：

1. rclone 兼容的 `X-OC-Mtime`；
2. 支持范围内的 PROPPATCH；
3. 服务端完成时间。

界面生成的 rclone remote 使用 `vendor=rclone`，使 rclone 按其 WebDAV 兼容路径处理 mtime。
文件 PROPPATCH 可以用一次“相同 Content Ref、更新 mtime”的原子事务实现，不重写 S3 内容；
目录 mtime 修改第一版返回属性不可修改，不为此扩展 PVLog 格式。

## 9. MOVE、COPY 与覆盖

解析 `Destination` 时：

- 接受相对或绝对 URL；
- 只使用同一固定 Wormhole root 下的 path；
- 不发起网络请求；
- 拒绝移动到自身后代；
- 目标父目录必须存在。

`Overwrite: F` 且目标存在时返回 `412`。

`Overwrite: T` 或缺省时：

- 目标不存在：普通 move/copy；
- 目标存在：在一个 PVLog batch 中删除目标并移动/复制源；
- 不允许覆盖 root；
- 目录覆盖规则保持克制：目标目录非空时拒绝 `409`，不做递归合并。

COPY 继续复用不可变 Content Ref，不重新下载或上传内容。目录 COPY 受现有 10,000 条 batch
限制。

## 10. 条件请求与并发

支持最必要条件：

- `If-Match`；
- `If-None-Match: *`；
- `Overwrite`；
- WebDAV lock token `If`；
- `Lock-Token`。

每个变更：

1. 在一个 Index revision 上解析路径和前置条件；
2. 生成事务；
3. Ref CAS 发布；
4. 发生无关 revision 竞争时最多重新解析并重试 3 次；
5. 目标或父目录语义已经变化时返回 `409` 或 `412`，不盲目重试。

同一文件上传在开始时固定 old FID；上传过程中内容被修改时永不覆盖新版本。Wormhole 不做
实时协同编辑，也不实现内容合并。

## 11. LOCK / UNLOCK

为 Windows Explorer、Finder 和常见 WebDAV 客户端提供最小独占写锁：

- 锁表进程内保存；
- token 使用安全随机 UUID；
- 支持 existing resource 和 lock-null path；
- 既有资源锁绑定稳定 Entry ID，重命名或移动后仍跟随该 Entry；
- lock-null 绑定规范化路径，首次成功 PUT 后提升为 Entry ID 锁；
- `Depth: 0`；
- 客户端申请 `Infinite` 时截断为 10 分钟；
- 支持带 token 的刷新；
- 最多 1024 个活动锁；
- 写方法校验目标及父路径相关锁；
- 锁冲突返回 `423 Locked`；
- disable、rotate、宿主重启清空全部锁。

锁只协调 Wormhole 客户端，不能阻止 Biunivers 文件管理器或第三方资源会话修改文件。因此
最终防丢失边界仍是 Content FID、revision 和 PVLog CAS，而不是 WebDAV 锁。

## 12. 空目录与平台元数据

File Service 有真实目录 Entry，因此 WebDAV/rclone 可保留空目录。

`.DS_Store`、`._*`、`Thumbs.db` 等平台文件按普通文件处理。V0.11 不自动过滤，避免同步结果
与用户选择不一致；未来若出现真实需求，可在命令生成器中增加显式过滤选项。

## 13. 关闭与故障

关闭或轮换：

- 新请求立即返回统一 401；
- 活动 GET/PUT/PROPFIND 被 abort；
- 未发布 PUT 不更新 Ref；
- 已经完成 CAS 的写入不会回滚；
- 锁表清空；
- 可能已经写入但未被引用的 Chunk 保持不可变，成为未来 GC 候选。

File Service 进入 offline：

- 控制界面显示不可用；
- Wormhole 自动关闭；
- WebDAV 返回 `503`，但不泄漏 S3 或 RefStore 错误详情。

## 14. 资源限制

第一版建议：

- XML 请求体：64 KiB；
- 单文件：4 GiB；
- PROPFIND：Depth 0/1；
- COPY：10,000 entries；
- 活动锁：1024；
- 同时内容传输：8；
- 同时元数据请求：32；
- 路径使用 File Service 现有名称和深度校验；
- 响应流尊重 Node 背压。

达到限制时返回明确的 WebDAV/HTTP 错误，不排队到无限内存。

## 15. rclone 命令生成

命令使用进程环境配置一个临时 remote：

```text
RCLONE_CONFIG_WORMHOLE_TYPE=webdav
RCLONE_CONFIG_WORMHOLE_URL=<URL>
RCLONE_CONFIG_WORMHOLE_VENDOR=rclone
RCLONE_CONFIG_WORMHOLE_USER=biunivers
RCLONE_CONFIG_WORMHOLE_PASS="$(rclone obscure '<10 位密码>')"
```

环境变量和 rclone 命令放在同一条 shell 语句中；不写入用户的持久 rclone 配置。`PASS` 由
目标机器本地执行 `rclone obscure`，浏览器不重新实现 rclone 的密码混淆算法。

Mount 模板：

```sh
mkdir -p "$HOME/Biunivers" && RCLONE_CONFIG_WORMHOLE_TYPE=webdav RCLONE_CONFIG_WORMHOLE_URL='<URL>' RCLONE_CONFIG_WORMHOLE_VENDOR=rclone RCLONE_CONFIG_WORMHOLE_USER=biunivers RCLONE_CONFIG_WORMHOLE_PASS="$(rclone obscure '<PASSWORD>')" rclone mount wormhole: "$HOME/Biunivers" --vfs-cache-mode writes --daemon
```

默认 `Biunivers → 本地` Sync 模板：

```sh
mkdir -p "$HOME/Biunivers-Sync" && RCLONE_CONFIG_WORMHOLE_TYPE=webdav RCLONE_CONFIG_WORMHOLE_URL='<URL>' RCLONE_CONFIG_WORMHOLE_VENDOR=rclone RCLONE_CONFIG_WORMHOLE_USER=biunivers RCLONE_CONFIG_WORMHOLE_PASS="$(rclone obscure '<PASSWORD>')" rclone sync --interactive --progress --create-empty-src-dirs wormhole: "$HOME/Biunivers-Sync"
```

选择反向同步时只交换最后两个位置参数。URL 和密码只允许预先校验过的字符；生成器仍采用
POSIX shell 单引号转义，不拼接任意用户脚本。

密码会出现在粘贴内容和 shell history 中，因此界面提醒用户完成传输后关闭 Wormhole 或轮换
密码。

Mount 使用 `--vfs-cache-mode writes`。Sync 必须带 `--interactive`，并根据用户选择交换源与
目标。第一版不自动安装 rclone、FUSE 或 macFUSE。

## 16. 测试基线

协议单元测试：

- path、XML、Basic、Depth、Range、Destination、Overwrite、If 和锁；
- 所有失败响应不得包含密码、S3 key、FID 之外的内部对象路径。

服务测试：

- create/read/write/move/copy/delete；
- >64 MiB Manifest；
- 并发 PUT；
- CAS 冲突；
- disable/rotate 中止；
- empty directory 和 Unicode。

真实兼容测试：

- rclone `lsd`、`copy`、`mount`、两个方向 `sync --interactive`；
- Windows Explorer 映射、基本 CRUD；
- macOS Finder 基本 CRUD；
- HTTPS 反向代理；
- 宿主重启后旧凭据失效。

Windows Explorer 已知存在默认 50 MB 文件限制和目录属性响应限制。这属于 Windows WebClient
边界；Wormhole 文档必须提示，不能通过服务端虚假宣称消除。
