# 浏览器云端个人桌面 V0.13 COW 提交、Diff 与导回局部设计

状态：已冻结

日期：2026-07-30

## 1. 输入与安全前提

提交器只接受一个已停止或已冻结 Run：

```text
runId
workspaceId
inputHead
upperPath（由 Runtime 解析，不由 HTTP 提交）
```

提交前必须确认：

- Run 持有 Workspace 写租约；
- Workspace Ref 仍等于 `inputHead`；
- 容器不能继续写 Upper；
- Lower 与 Snapshot 对应同一 `inputHead`；
- Upper 位于该 Run 的固定根目录内；
- 扫描未越过 mount、symlink 或宿主路径边界。

## 2. V0.13 支持的 Upper 语义

接受：

- 新建普通文件和目录；
- 覆盖、截断普通文件；
- 删除文件和目录；
- 重命名，规范化为删除加创建；
- fuse-overlayfs 同名字符设备 whiteout；
- `user.fuseoverlayfs.opaque=y` 目录。

拒绝整次提交并保留 Upper：

- symlink；
- device（合法 whiteout 除外）；
- FIFO、socket；
- hardlink `nlink > 1`；
- ACL 或未知安全相关 xattr；
- whiteout/opaque 的未知表示；
- 非 UTF-8 名称；
- 名称、深度、文件数、单文件或总新增 bytes 超限；
- 扫描期间 Upper 发生变化。

拒绝不是静默忽略。错误必须指出首个不支持路径和原因。

## 3. Upper 解释

提交器先从固定 Lower EntryIndex 构造逻辑树，再按 Upper 应用：

1. 普通 Upper 文件替换同路径 Lower 文件；
2. 普通 Upper 目录与同路径 Lower 目录合并；
3. whiteout 删除同目录下同名 Lower 节点；
4. opaque 目录先隐藏全部 Lower 子项，再加入 Upper 子项；
5. 新 Upper 路径加入目标树；
6. 最终树再次执行唯一名称、父子关系和限制校验。

扫描采用目录 fd/`openat` 风格和 `NOFOLLOW` 语义；不通过字符串拼接追踪不可信 symlink。

## 4. Entry ID 与内容

- 未被替换且路径未变化的 Lower Entry 保留 Entry ID；
- 新建文件/目录使用新随机 Entry ID；
- 删除后同名重建视为新 Entry；
- 重命名第一版表示删除加创建，因此不保证保留 Entry ID；
- 未修改文件继续引用原 Content FID；
- Upper 普通文件按 64 MiB 分片，客户端计算 XXH3-128，上传并校验；
- 内容相同天然复用既有 FID。

mtime 取冻结后 Upper stat；createdAt 对新 Entry 取提交时间，保留 Entry 沿用原值。
PVLog V1 没有独立的目录元数据更新操作，因此普通既有目录只发生子项变化时保留原 mtime；
新建或 opaque 替换目录仍使用 Upper mtime。该限制不影响文件内容和树结构语义。

## 5. 发布事务

```text
freeze/stop
→ 扫描并规范化 Upper
→ 构造目标 Entry projection
→ 写新增 Chunk/Manifest
→ 写 Segment
→ 写 Checkpoint
→ 写 Head(input revision + 1)
→ 回读并验证对象
→ SQLite CAS Workspace Ref
→ Run = COMMITTED, outputHead = new Head
→ 清除写租约
```

不可变对象先写、Ref 最后 CAS。CAS 失败：

- 不覆盖 Workspace Ref；
- Run 进入 `CONFLICT`；
- Upper 保留；
- 已写对象成为未引用候选；
- 第一版不自动 rebase 或 merge。

SQLite 中 Ref CAS、Run 终态、`output_head_fid` 与写租约清除必须处于同一事务。

若规范化后的目标树与输入 Head 完全相同，不写空 Segment，也不增加 revision。宿主仍须在
一个 SQLite 事务中确认 Ref 未变化、将 Run 标记为 `COMMITTED`、把 output Head 设为输入
Head 并释放写租约；若确认时 Ref 已变化，则进入 `CONFLICT`。

## 6. Diff

Diff 比较 Workspace `baselineHead` 与当前已发布 Head，而不是读取活动 Upper。

第一版输出：

- path；
- `added/modified/deleted`；
- 旧/新 kind、size、mtime、Content FID；
- UTF-8 小文本的统一 Diff；
- 二进制或超限文本只显示元数据变化。

由于第一版重命名不保留 Entry ID，Diff 不单独声称 rename；界面可把相同 FID 的删除和新增
提示为“疑似移动”，但它不是提交语义。

## 7. 导回 main

用户在 Workspace 应用中选择已发布结果和 `main` 目标目录。导回调用现有 main
FileSystemTransactions：

- 文件与目录递归复制；
- Content FID 直接复用，不从 S3 下载再上传；
- 为 main 创建新 Entry ID；
- 同名冲突必须在执行前选择“跳过、改名或覆盖”；
- 第一版默认改名或取消，不自动覆盖；
- 整批操作使用单次原子事务；
- 不传播 Workspace 删除到 main；
- 不修改 Workspace baseline。

活动 Upper 不能直接导回；必须先提交为 Workspace Head。

## 8. 丢弃与保留

- `STOPPED` Run 可丢弃：删除 Upper，Run 进入 `DISCARDED`，Workspace Ref 不变；
- `FAILED/CONFLICT` 默认保留 Upper，直到用户明确丢弃或 retention 到期；
- `COMMITTED` Upper 在提交验证完成后可删除；
- 清理失败不回滚已发布 Ref，只记录需要重试的 Runtime cleanup；
- 临时 Workspace 的 retention 从最后一个非终态 Run 完成后开始计算。

## 9. 明确延期

- 自动三方合并；
- rename identity；
- 增量持续提交；
- 活动 Upper 实时 Diff；
- symlink/hardlink；
- POSIX owner、ACL、xattr 迁移；
- 从 main 删除或覆盖的自动同步；
- GC 物理删除。
