# 浏览器云端个人桌面 V0.13 Workspace 控制面局部设计

状态：已冻结

日期：2026-07-30

## 1. 本文冻结什么

本文只冻结 Workspace、Ref、Run 和写租约的控制状态。文件挂载与 COW 提交分别由另外两份
局部设计约束。

第一版坚持：

- 一个 Workspace 恰好对应一个 `ws-*` Ref；
- Workspace 与 Ref 位于同一个 RefStore SQLite；
- 浏览器只见 `workspaceId`，不见也不能指定 `refId`；
- 一个 Workspace 同时最多一个写 Run；
- Workspace 创建、删除与 Ref 可达性变化必须原子提交；
- `main` 的现有外部行为不变。

## 2. 标识

- `workspace_id`、`run_id`：随机 16 bytes，数据库存 BLOB，HTTP 表示为 32 位小写 hex；
- `ref_id`：服务端生成的 `ws-<workspace-id-hex>`，不作为外部能力；
- `head_fid`、`lineage_id`：16 bytes；
- `executor_id`：第一版只能取系统注册表中的固定诊断执行器 ID。

客户端提交来源 Entry ID，不提交来源路径作为身份。显示名称和路径仅用于界面与冲突提示。

## 3. SQLite Schema

Schema 与 `filesystem_refs` 同库、同版本迁移：

```sql
CREATE TABLE workspace_records (
  workspace_id BLOB PRIMARY KEY CHECK(length(workspace_id) = 16),
  ref_id TEXT UNIQUE NOT NULL
    REFERENCES filesystem_refs(ref_id) ON DELETE RESTRICT,
  name TEXT NOT NULL,
  source_ref_id TEXT NOT NULL,
  source_head_fid BLOB NOT NULL CHECK(length(source_head_fid) = 16),
  baseline_head_fid BLOB NOT NULL CHECK(length(baseline_head_fid) = 16),
  state TEXT NOT NULL CHECK(state IN ('READY', 'DELETING')),
  retention TEXT NOT NULL CHECK(retention IN ('TEMPORARY', 'KEPT')),
  active_write_run_id BLOB,
  created_at_ms INTEGER NOT NULL,
  updated_at_ms INTEGER NOT NULL,
  FOREIGN KEY(active_write_run_id) REFERENCES workspace_runs(run_id)
);

CREATE TABLE workspace_runs (
  run_id BLOB PRIMARY KEY CHECK(length(run_id) = 16),
  workspace_id BLOB NOT NULL
    REFERENCES workspace_records(workspace_id) ON DELETE RESTRICT,
  executor_id TEXT NOT NULL,
  input_head_fid BLOB NOT NULL CHECK(length(input_head_fid) = 16),
  output_head_fid BLOB CHECK(output_head_fid IS NULL OR length(output_head_fid) = 16),
  state TEXT NOT NULL CHECK(state IN (
    'PREPARING', 'RUNNING', 'STOPPED', 'COMMITTING',
    'COMMITTED', 'CONFLICT', 'FAILED', 'DISCARDED'
  )),
  runtime_identity TEXT,
  error_code TEXT,
  created_at_ms INTEGER NOT NULL,
  started_at_ms INTEGER,
  finished_at_ms INTEGER
);
```

`active_write_run_id` 是第一版写租约，不再增加独立 Lease 表。它由控制服务和 Run 状态在同一
SQLite 事务中设置或清除。第一版是单宿主控制服务，不引入分布式心跳和租约超时。

删除 Workspace 时先确认无活动 Run，再在一个事务内删除历史 Run、Workspace record 和对应
`filesystem_refs` 行。S3 不执行同步删除。

## 4. Workspace 创建事务

创建请求包含：

- 名称；
- 同一来源目录中的 Entry ID 集合；
- retention。

执行顺序：

1. 读取并固定 `main` Ref 为 `sourceHead`；
2. 从该 Head 加载 EntryIndex；
3. 校验选择均为该目录的直接子项，递归展开目录；
4. 校验文件数、深度、元数据大小和重名；
5. 生成新 lineage、虚拟根和全部新 Entry ID；
6. 复用文件 Content FID，写 revision 0 Checkpoint 与 Genesis Head；
7. 再次确认 `main` 仍等于 `sourceHead`；
8. 在一个 SQLite 事务中创建 `ws-*` Ref 与 Workspace record。

第 6 步产生的不可变对象即使事务失败也只是未引用对象，可由未来 GC 识别，不回滚 S3。

## 5. Run 状态机

```text
PREPARING → RUNNING → STOPPED → COMMITTING → COMMITTED
     │          │         │          ├────→ CONFLICT
     └──────────┴─────────┴──────────→ FAILED
                          └───────────→ DISCARDED
```

规则：

- 创建 `PREPARING` Run 时，将 Workspace `active_write_run_id` 原子设为该 Run；
- `input_head_fid` 固定为当时 Workspace Ref 的 Head；
- `RUNNING` 只表示容器已启动，不表示 iframe 窗口存在；
- 正常停止进入 `STOPPED`，Upper 仍保留且写租约仍持有；
- `COMMITTED`、`CONFLICT`、`FAILED`、`DISCARDED` 是终态，并清除写租约；
- `CONFLICT` 和可恢复 `FAILED` 保留 Upper；用户可检查后明确清理 Upper，但保留原终态审计
  记录，第一版不自动重试合并；
- 删除 Workspace 必须先让所有 Run 进入终态并完成 Runtime 清理。

## 6. 崩溃恢复

控制服务启动时读取所有非终态 Run，并调用 Runtime `inspect(runId)`：

- Runtime 与 mount 都存在：恢复显示状态，不自动启动新容器；
- 容器已退出但 Upper 存在：归一为 `STOPPED`；
- Runtime 记录不存在但 Upper 可恢复：归一为 `FAILED`，保留恢复路径；
- mount 或容器残留但数据库无 Run：Runtime 隔离并清理为 orphan，不创建猜测记录；
- Ref 已推进但 Run 尚未写入 `COMMITTED`：按 `output_head_fid` 和 Workspace Ref 对账后补全；
- 无法证明状态时不推进 Ref，不删除 Upper。

恢复完成前对应 Workspace 保持只读。

## 7. 内部服务边界

先把现有文件服务改为内部显式 Ref：

```ts
loadEntryIndex(repository, refStore, refId)
new FileSystemTransactions({ refId, repository, refStore })
```

默认参数不得隐式扩散。桌面、文件管理器、Resource Session、Wormhole 继续由组装层明确传入
`main`；只有 Workspace Service 能把 `workspaceId` 映射到 `ws-*`。

第三方协议和 public HTTP API 不增加任意 `refId` 参数。

## 8. GC 与备份

- RefStore 备份必须同时包含 Ref、Workspace、Run；
- GC root 从“只扫描 main”改为扫描全部 `filesystem_refs`；
- 活动 Run 的 `input_head_fid` 与尚未处理的 `output_head_fid` 也作为临时 root；
- 删除 Workspace 只移除 Ref 可达性，不直接删除不可变对象；
- GC 删除能力不在 V0.13 启用，但 root 计算必须先正确。

## 9. 明确不做

- Universe 表或 Universe Service；
- Workspace 独立数据库；
- 任意 Ref 浏览 API；
- 多写者、分布式 Lease、自动租约抢占；
- 从 `main` 自动同步后续变化；
- 自动三方合并；
- 第三方 Workspace App 安装协议。
