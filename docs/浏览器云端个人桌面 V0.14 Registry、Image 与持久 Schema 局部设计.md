# 浏览器云端个人桌面 V0.14 Registry、Image 与持久 Schema 局部设计

状态：实现基线

日期：2026-07-31

基线：V0.14 Biunivers Workspace Application 第三版概念设计

## 1. 范围

本设计只冻结 V0.14-A：

```text
公开 GHCR repository
→ Compute Runtime 拉取并检查
→ 固定本地实际 RepoDigest
→ 注册 BWA Application
→ 创建并独占绑定 Workspace
→ 保存 Instance 启动配置
```

本阶段不启动 BWA 容器，不实现 Runtime Proxy、iframe、自动启动、异常 Upper、
更新编排和卸载镜像清理。

## 2. 权威边界

持久状态只有两个权威载体：

1. File Service RefStore SQLite：Application、Instance、普通环境变量、Workspace、Ref
   及其关系；
2. 独立的敏感变量文件：只保存 secret 值，权限固定为 `0600`。

Instance 与 Workspace 的独占关系必须和 Workspace 记录处于同一个 SQLite 数据库，
否则无法原子创建、绑定、解绑和删除。因此第一版不另建 Application Manager 数据库。

OCI 镜像缓存不是权威注册表。Docker 本地镜像丢失后可以按已安装的
`repository@digest` 重新准备；Container ID 和本地 image ID 永不入库。

## 3. 身份与规范化

第一版用户安装输入只接受：

```text
ghcr.io/<owner>/<image>
ghcr.io/<owner>/<image>:<tag>
```

不接受 digest、URL scheme、凭据、端口、路径遍历、空 tag 或隐式 Docker Hub 名称。
owner、image 和 tag 采用 OCI/Docker 可移植字符子集；repository 统一转为小写。
省略 tag 时发现引用使用 `:latest`，但持久结果永远不保存 tag。

Runtime 返回：

```text
canonicalRepository = ghcr.io/owner/image
digest              = sha256:<64 lowercase hex>
imageReference      = canonicalRepository@digest
labels              = 经过大小和字段白名单限制的字符串
entrypoint           = string[]
cmd                  = string[]
```

Application 的长期主键是 `canonicalRepository`。安装版本是 digest。一次 tag 拉取完成后，
只有 Docker 返回的本地 `RepoDigests` 中与 canonical repository 精确匹配的一项可以成为
安装结果，拒绝无 RepoDigest、多个不同匹配 digest 或格式异常。

## 4. Image API

Compute Runtime Unix socket 新增两个窄操作：

```text
pullAndInspect(reference)
inspectInstalled(imageReference)
```

### 4.1 pullAndInspect

```text
校验公开 GHCR 引用
→ docker pull <validated reference>
→ docker image inspect <validated reference>
→ 校验 RepoDigest、架构、Config.Labels、Entrypoint、Cmd
→ 返回窄结果
```

它不接受 registry 凭据、Docker 参数、平台覆盖或任意 executable。命令输出、超时和
字段长度均有限制。Docker stderr 不原样返回 Manager，防止意外泄露环境信息。

### 4.2 inspectInstalled

只接受已经规范化的 `repository@sha256:digest`，不执行 pull。它用于重启后校验本地
镜像和显示已安装元信息；本地镜像不存在不是注册丢失。

### 4.3 强制元信息

镜像必须满足：

```text
io.biunivers.workspace-application.protocol=1
org.opencontainers.image.description=<非空纯文本>
org.opencontainers.image.source=https://...
```

限制：

- label 总序列化大小不超过 32 KiB；
- description UTF-8 不超过 2 KiB，不接受控制字符；
- source 不超过 2 KiB，只接受 HTTPS URL，不接受用户名和密码；
- Entrypoint 与 Cmd 合计不超过 128 项、16 KiB；
- protocol 必须精确为字符串 `1`，不做猜测兼容。

Manager 只持久化协议需要的展示字段，不保存任意 label 副本。

## 5. RefStore Schema v3

Schema v2 原子迁移到 v3。新增表如下，均使用 SQLite `STRICT` 表。

### 5.1 bwa_applications

```sql
CREATE TABLE bwa_applications (
  application_id TEXT PRIMARY KEY,
  installed_digest TEXT NOT NULL,
  previous_digest TEXT,
  protocol_version INTEGER NOT NULL CHECK(protocol_version = 1),
  title TEXT NOT NULL,
  description TEXT NOT NULL,
  source_url TEXT NOT NULL,
  image_version TEXT,
  image_revision TEXT,
  image_licenses TEXT,
  enabled INTEGER NOT NULL CHECK(enabled IN (0, 1)),
  default_instance_id BLOB,
  created_at_ms INTEGER NOT NULL CHECK(created_at_ms >= 0),
  updated_at_ms INTEGER NOT NULL CHECK(updated_at_ms >= created_at_ms),
  FOREIGN KEY(default_instance_id) REFERENCES bwa_instances(instance_id)
    DEFERRABLE INITIALLY DEFERRED
) STRICT;
```

`application_id` 是规范化 repository。digest 单独存放，不把 tag 和完整 image reference
混入身份。`title` 缺省为 repository 最后一段；它不是身份。

### 5.2 bwa_instances

```sql
CREATE TABLE bwa_instances (
  instance_id BLOB PRIMARY KEY CHECK(length(instance_id) = 16),
  application_id TEXT NOT NULL REFERENCES bwa_applications(application_id),
  workspace_id BLOB UNIQUE NOT NULL
    REFERENCES workspace_records(workspace_id) ON DELETE RESTRICT,
  desired_state TEXT NOT NULL CHECK(desired_state IN ('STOPPED', 'RUNNING')),
  startup_policy TEXT NOT NULL
    CHECK(startup_policy IN ('MANUAL', 'ON_OPEN', 'AUTOMATIC')),
  display_name TEXT NOT NULL,
  created_at_ms INTEGER NOT NULL CHECK(created_at_ms >= 0),
  updated_at_ms INTEGER NOT NULL CHECK(updated_at_ms >= created_at_ms)
) STRICT;
```

`UNIQUE(workspace_id)` 实施一个 Workspace 最多绑定一个 Instance。活动 Run 和 observed
state 不在此表重复保存。

### 5.3 bwa_environment

```sql
CREATE TABLE bwa_environment (
  instance_id BLOB NOT NULL
    REFERENCES bwa_instances(instance_id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  value TEXT,
  sensitive INTEGER NOT NULL CHECK(sensitive IN (0, 1)),
  PRIMARY KEY(instance_id, name),
  CHECK(
    (sensitive = 0 AND value IS NOT NULL) OR
    (sensitive = 1 AND value IS NULL)
  )
) STRICT;
```

敏感变量在主库只保存名称和 `sensitive=1`，值保存在敏感变量文件。变量名匹配
`^[A-Za-z_][A-Za-z0-9_]{0,127}$`，拒绝 `BIUNIVERS_` 前缀、NUL 和重复名称。普通值单项
不超过 64 KiB，每 Instance 名称和值合计不超过 256 KiB，变量总数不超过 256。

## 6. 敏感变量文件

第一版使用一个 Manager 管理的 JSON 文件，例如：

```text
/data/private/bwa-secrets.json
```

格式由宿主内部版本化，逻辑键为 `instanceId/name`。目录权限 `0700`，文件权限 `0600`。
更新使用同目录临时文件、`fsync`、原子 rename；日志只出现变量名，不出现值。

SQLite 与文件无法组成真正的跨介质事务，因此操作顺序固定：

```text
写入/更新 secret：先原子写 secret 文件，再提交 SQLite 名称索引
删除 secret：先提交 SQLite 删除，再从 secret 文件清理孤儿
启动读取：SQLite 声明为 sensitive 但值缺失时拒绝启动
启动恢复：secret 文件中的孤儿允许安全清理，不自动重新绑定
```

这保证失败时最多产生不可达的 secret，不会让普通值被误当作 secret，也不会静默以空值
启动应用。

## 7. 原子操作

### 7.1 注册 Application

注册只消费 Runtime 已校验的 Image Inspection。事务内插入 Application；同 repository
已存在时返回 `APPLICATION_ALREADY_EXISTS`，不静默更新 digest。

### 7.2 创建空白 Instance

空白 Workspace 的不可变 genesis 对象可以在事务前写入 WORM Store，因为未引用对象无害。
随后在同一 SQLite 事务中：

```text
创建 Workspace Ref
→ 创建 workspace_records
→ 创建 bwa_instances
→ 若 Application 尚无 default，设置 default_instance_id
```

任一步冲突则全部回滚。第一版复用 WorkspaceDeriver 的 genesis 构造，但补充“空选择”专用
入口；不能用允许用户选择的接口伪造根目录。

### 7.3 从已有 Workspace 创建

必须先 Fork 新 Workspace，再在同一发布事务中绑定 Instance。不得把已有 Workspace 原地
占用。V0.14-A 可以先完成空白来源，其余两种来源属于相同 Schema，不阻塞 Image/Registry
闭环。

### 7.4 删除 Instance

V0.14-A 只提供“解绑并保留 Workspace”：

```text
确认没有活动写 Run
→ 删除 environment 行
→ 删除 Instance
→ 必要时清空或重新指定 default
→ Workspace 保持 READY/KEPT
→ 清理已不可达 secret
```

同时删除 Workspace 留到完整 Lifecycle 接入后实现，避免越过异常 Upper 门禁。

### 7.5 删除 Workspace

通用 `deleteWorkspace` 在存在 `bwa_instances.workspace_id` 外键时必须失败并返回明确的
`WORKSPACE_BOUND`，不能把约束错误误报为数据库损坏。

## 8. Registry 服务边界

Registry 服务只提供：

```text
register(inspectedImage)
listApplications()
getApplication(applicationId)
setEnabled(applicationId, enabled)
createBlankInstance(applicationId, config)
listInstances(applicationId)
getInstance(instanceId)
updateEnvironment(instanceId, ordinary, sensitive)
deleteInstancePreservingWorkspace(instanceId)
```

它不接受 Docker 参数，不直接调用 Docker socket，不派生 observed state，也不启动 Run。
HTTP 管理路由在后续接 UI 时复用该服务；V0.14-A 先通过单元和集成测试验证服务本身。

## 9. 错误与恢复

稳定错误码至少包括：

```text
IMAGE_REFERENCE_INVALID
IMAGE_PULL_FAILED
IMAGE_INSPECTION_INVALID
BWA_PROTOCOL_UNSUPPORTED
APPLICATION_ALREADY_EXISTS
APPLICATION_NOT_FOUND
APPLICATION_DISABLED
INSTANCE_NOT_FOUND
WORKSPACE_BOUND
ENVIRONMENT_INVALID
SECRET_VALUE_MISSING
```

错误消息不得包含 secret、Docker 命令完整环境或 registry 认证材料。Schema 迁移失败必须
整体回滚并保持 v2 可重新打开；v3 备份必须同时包含 BWA 关系，敏感变量文件由数据卷备份
流程单独覆盖。

## 10. V0.14-A 验收出口

- v2 RefStore 原子迁移为 v3，未来版本仍失败关闭；
- Application repository/digest/metadata 能跨重启保持；
- 一个 Workspace 不能绑定两个 Instance；
- Application、首个 Instance、default Instance 和空白 Workspace 原子建立；
- 已绑定 Workspace 不能由通用入口删除；
- 普通变量和敏感变量不会混储，敏感值不出现在数据库、日志和普通导出；
- Runtime 只接受公开 GHCR 窄引用，只返回本地真实 RepoDigest；
- tag 改变不会改变已注册 digest；
- Manager 测试替身无法借 Image API 注入 Docker 参数；
- 现有 V0.13 Workspace/Run/备份恢复测试全部保持通过。

达到以上出口后才进入 Lifecycle、提交与异常恢复局部设计。
