# 浏览器云端个人桌面 V0.12 普通文件 Identicon 设计

状态：已施工，待真实界面验收

日期：2026-07-30

## 1. 目标

仅把“没有专用图标的普通文件”的默认 `📄` 替换为基于稳定 Entry ID 生成的 Identicon。

Identicon 提供文件级视觉身份：

- 改名、移动和内容更新不改变图案；
- 复制产生新 Entry ID，因此产生新图案；
- 不保存图片，不增加数据库字段；
- 不访问网络，不把 Entry ID 发送给外部服务。

## 2. 范围

第一版只处理现有界面中使用默认普通文件符号的位置：

1. 文件管理器列表视图；
2. 文件管理器图标视图；
3. 桌面普通文件项目；
4. 宿主文件选择器中的普通文件。

以下内容保持不变：

- 目录继续显示现有文件夹图标；
- 应用继续显示应用图标；
- 已有专用图标的文件继续优先显示专用图标；
- 不可用桌面项目继续使用既有虚化和失效状态；
- 不增加缩略图、媒体封面、扩展名角标或图标设置；
- 不修改 File Service、Entry 投影、PVLog、S3 或第三方应用协议。

当前文件管理器和文件选择器没有专用文件图标字段，因此其中所有普通文件都会使用
Identicon。这个事实不构成新的后端约定。

## 3. 图标选择规则

统一优先级：

```text
目录
  → 现有文件夹图标

普通文件 + 有专用图标
  → 专用图标

普通文件 + 无专用图标 + Entry ID 合法
  → Entry Identicon

普通文件 + Entry ID 异常
  → 现有默认文件符号
```

“专用图标”只指调用方已经取得并信任的图标 URL。V0.12 不设计专用图标的发现、注册或
生成机制。

## 4. 生成器选择

第一实现候选采用
[Jdenticon 3.3.0](https://www.npmjs.com/package/jdenticon)，MIT 许可证。

选择原因：

- 专门生成确定性 Identicon，不是完整头像系统；
- 支持浏览器内直接更新 SVG；
- 32 位十六进制 Entry ID 会被识别为现成 hash，不需要文件名或内容 FID；
- `updateSvg()` 适合只使用 SVG 的场景，官方说明这种专用入口更利于 bundler 优化；
- 无网络请求，无运行时服务依赖；
- 输出只由库控制的 SVG 几何图形组成。

不采用：

- DiceBear：能力和样式包超出当前单一用途；
- Boring Avatars：更偏头像视觉，不如经典 Identicon 符合文件身份语义；
- 远程 Identicon API：会泄露标识、引入可用性依赖和 CSP 配置。

### 4.1 包体门槛

施工时必须比较引入前后的 Vite 生产构建 gzip 体积：

- Jdenticon 导致主客户端 gzip 增量不超过 20 KiB：保留；
- 超过 20 KiB，或无法被当前 Vite 配置正确裁剪 Node/Canvas 代码：停止接入；
- 回退为仓库内极简的确定性镜像网格实现，不为了沿用组件而接受明显包体浪费。

不得使用 CDN 或动态远程加载规避门槛。

## 5. 共享组件

新增单一展示组件：

```tsx
<EntryIdenticon entryId={entryId} size={42} />
```

建议接口：

```ts
interface EntryIdenticonProps {
  entryId: string;
  size: number;
  className?: string;
}
```

组件行为：

1. 只接受 `/^[0-9a-f]{32}$/` 的 Entry ID；
2. 使用 `useRef<SVGSVGElement>` 和 `useEffect`；
3. 调用 `updateSvg(svgElement, entryId, localConfig)`；
4. 不使用全局 Jdenticon 配置，避免影响其他消费者；
5. SVG 设置固定 `viewBox`、传入尺寸和 `aria-hidden="true"`；
6. 不在 DOM 中写入 `data-jdenticon-hash`，避免无必要地暴露 Entry ID；
7. 非法 ID 回退为默认文件符号，不让视觉组件破坏文件操作。

组件可以使用 `memo`，但不增加生成结果缓存。SVG 生成成本低，React 已通过稳定 key 复用
同一文件的组件实例。

## 6. 各界面接入

### 6.1 文件管理器列表

用 18–20 px Identicon 替换文件行中的 `📄`。目录仍为 `📁`。图标不得改变名称列、行高、
Shift/Ctrl 选择和双击行为。

### 6.2 文件管理器图标视图

用约 42 px Identicon 替换大号 `📄`。现有网格尺寸、框选命中区域和文件名布局保持不变；
Identicon 本身设置 `pointer-events: none`。

### 6.3 桌面

`DesktopTargetIcon` 保持现有判断顺序：

1. `item.resolved.icon` 存在时显示该专用图标；
2. directory 显示文件夹；
3. file 使用 `item.target.handle` 作为 Entry ID 生成 Identicon。

桌面引用的 file handle 就是稳定 Entry ID，不新增 Resolver 字段。

### 6.4 宿主文件选择器

普通文件使用小号 Identicon，目录不变。该改动只影响宿主 UI，不向 iframe 或第三方应用
交付 SVG。

## 7. 稳定性与安全

- 身份输入只能是 Entry ID，禁止使用文件名、路径或 Content FID；
- Identicon 不是校验标识，不能代替 Entry ID、FID 或内容验证；
- 不根据扩展名改变配色，避免改名导致视觉身份改变；
- 不把 Identicon 持久化到 S3、SQLite、localStorage 或桌面表；
- 不从生成 SVG 中恢复或展示 Entry ID；
- 组件必须由可信的内部 Entry 数据调用；
- 依赖版本固定在 lockfile 中，并保留 MIT 许可证信息。

Entry ID 是随机 128-bit 标识。Jdenticon 将合法十六进制输入作为 hash 使用，因此输出稳定；
图案相似或碰撞不影响任何业务语义。

## 8. 测试

自动测试至少覆盖：

- 相同 Entry ID 生成相同 SVG；
- 不同 Entry ID 生成不同 SVG；
- 非法 Entry ID 使用回退符号；
- 列表视图普通文件使用 Identicon，目录仍使用文件夹；
- 图标视图普通文件使用 Identicon，框选和双击不回归；
- 桌面专用图标优先于 Identicon；
- 桌面普通文件使用 handle 生成 Identicon；
- 宿主文件选择器目录/文件分支正确；
- 全量 Vitest、TypeScript、生产构建和 ESLint 通过；
- 记录引入依赖前后的 gzip 体积。

人工验收：

- 同一文件在列表、图标视图、桌面和文件选择器中图案一致；
- 改名、移动、内容更新后图案不变；
- 复制后原件和副本图案不同；
- 小尺寸仍可辨认，不挤压文件名；
- 选中、虚化、悬停和框选状态仍清晰。

## 10. 闭环结论

设计闭环。

它只替换已有默认文件符号，使用系统现成的稳定 Entry ID，不新增存储、接口、协议、配置
或后台任务。Jdenticon 是实现候选而不是不可替换的架构依赖；明确的包体门槛保证这一项
视觉增强不会反过来增加不成比例的系统复杂度。
