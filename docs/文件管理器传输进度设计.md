# 文件管理器传输进度设计

状态：已实现，待人工验收

日期：2026-07-29

## 范围

内部文件管理器为当前前台上传或下载显示：

- 文件名；
- 多文件上传的当前序号；
- 已传输字节和总字节；
- 可计算时的百分比；
- 原生进度条；
- 取消按钮。

同一文件管理器窗口第一版只执行一个传输任务。传输期间沿用 `working` 状态，避免文件树
修改、重复上传或重复下载与当前任务竞争。

## 实现

浏览器 Fetch API 不提供可靠的上传进度事件，因此上传的数据 PUT 使用
`XMLHttpRequest.upload`；创建待保存句柄、签发 transfer 和释放句柄仍使用现有 Host API。

下载继续使用 Fetch，但通过 `Response.body` reader 逐块累计。总大小优先采用响应
`Content-Length`，缺失时使用文件元数据大小。下载完成后才生成 Blob URL 并触发浏览器保存。

上传和下载都接受 `AbortSignal`。取消或文件管理器卸载时：

1. 中止当前 XHR 或 Fetch；
2. 释放宿主文件句柄；
3. 清除进度状态；
4. 显示“已取消”，不把用户取消报告为系统错误。

## 明确不做

- 后台传输中心；
- 页面刷新后的任务恢复；
- 并行多文件上传；
- 断点续传；
- 服务端持久化进度；
- 下载到磁盘时绕过浏览器 Blob 内存。

这些能力需要独立协议和生命周期设计，不属于本次体验修复。

## 自动化验证

- 上传进度事件映射到字节与百分比；
- 下载流按实际读取字节累计；
- 多文件上传序号；
- 取消会触发 AbortSignal；
- 完成后仍释放句柄并撤销 Blob URL；
- 完整前端与服务端回归通过。
