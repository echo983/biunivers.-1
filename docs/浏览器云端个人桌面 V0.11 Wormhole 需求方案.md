# 浏览器云端个人桌面 V0.11 Wormhole 需求方案

状态：设计基线

日期：2026-07-30

## 1. 定位

Wormhole 是 Biunivers 的按需文件传输、远程挂载与批量同步通道。

它通过可开关的 WebDAV 读写入口，把当前 Biunivers File Service 文件树交付给用户自己的
Windows、macOS 或 Linux 设备。Wormhole 不在后台主动同步，不维护设备副本，也不提供实时
双向冲突合并。

产品表述统一为：

> 开启后，外部设备可以通过 WebDAV 读写 Biunivers 文件。Wormhole 不会在后台主动同步
> 任何设备。

## 2. 用户价值

现有上传、原文件下载和目录 ZIP 解决浏览器内的偶发交换；Wormhole 补齐以下场景：

- 在 Windows Explorer 或 macOS Finder 中直接浏览和修改 Biunivers 文件；
- 在 Linux 或 macOS 中通过 rclone 挂载为一个远程目录；
- 用户主动运行 rclone，把一个本地目录与 Biunivers 做方向明确的批量同步；
- 不安装 Biunivers 专用客户端，不开放 SMB，不额外维护 SFTP 文件树。

## 3. 系统应用

新增编译期白名单 internal 应用：

```text
system.wormhole
```

显示名：`Wormhole`

Wormhole 确实需要控制宿主文件协议入口、读取运行状态和生成临时凭据，符合 internal 特权层
的必要条件。它不向第三方 Static App、Host API 或 Resource Session 开放目录遍历能力。

建议窗口：

- 默认尺寸：680 × 600；
- 最小尺寸：520 × 420；
- 默认不固定到任务栏；
- 默认不放置桌面图标，可由用户从应用菜单添加。

## 4. 开关与凭据

Wormhole 默认关闭。

开启条件：

- File Service 状态为 `ready` 且可写；
- 宿主能够创建安全随机凭据；
- 用户明确点击开启。

开启时：

- 用户名固定为 `biunivers`；
- 生成随机 10 位密码；
- 字符表排除 `0/O`、`1/l/I` 等易混淆字符；
- 约 58 bit 随机强度；
- 显示 WebDAV URL、用户名和密码；
- 提供逐项复制按钮；
- 生成平台说明和可复制 rclone 命令。

状态仅保存在当前 Biunivers 服务进程内：

- 不把密码写入 SQLite、JSON、日志、环境变量或 S3；
- 宿主重启后 Wormhole 自动关闭；
- 每次从关闭切换为开启都生成新密码；
- “轮换密码”立即生成新密码并撤销旧密码；
- “关闭”立即撤销凭据并终止活动 Wormhole 请求。

内建界面可以在开启期间重新读取并显示进程内密码。能访问 Biunivers 桌面的人本来就能操作
用户文件，因此不再为密码显示引入第二套桌面登录。

## 5. 界面

主状态卡：

- `已关闭` / `已开启`；
- 开关；
- WebDAV 地址；
- 用户名；
- 密码；
- 复制按钮；
- 轮换密码；
- HTTPS 安全状态；
- “宿主重启后自动关闭”的提示。

连接说明分三部分：

### Windows

- 主推 Explorer“映射网络驱动器/添加网络位置”；
- 显示 URL、用户名和密码；
- 可额外给出 `net use` 示例，但不把它计入两条主命令；
- 明示 Windows WebClient 的大文件、超大目录和大小写兼容边界；
- 大文件场景建议改用 rclone。

### macOS

- Finder 可通过“前往 → 连接服务器”直接使用 WebDAV；
- 高级挂载和同步仍推荐 rclone。

### Linux / macOS rclone

界面只提供两条主命令：

1. Mount；
2. Sync。

两条命令都包含临时的 rclone WebDAV 配置，不要求用户先进入交互式 `rclone config`。

Mount 默认：

- 挂载点为 `$HOME/Biunivers`；
- 自动创建挂载点；
- 使用 `--vfs-cache-mode writes`；
- 使用 `--daemon`；
- 保留明显的卸载说明。

Sync 必须先由用户选择方向：

- `Biunivers → 本地`，默认；
- `本地 → Biunivers`。

默认本地目录为 `$HOME/Biunivers-Sync`。命令带：

- `--interactive`；
- `--progress`；
- `--create-empty-src-dirs`。

界面必须提醒：`rclone sync` 会删除目标端多余文件。第一版不提供 `bisync`。

## 6. 地址与 HTTPS

固定 WebDAV 路径：

```text
/wormhole/webdav/
```

界面使用当前浏览器的 `window.location.origin` 生成可复制 URL，避免反向代理后的公网地址与
宿主内部 `BIUNIVERS_DESKTOP_ORIGIN` 不一致。

服务端只依赖路径，不根据客户端提供的 Host 构造安全决策。`MOVE`/`COPY` 的绝对
`Destination` 只提取并校验同一 Wormhole 路径，不发起外部网络请求。

正式使用必须部署在 HTTPS 后：

- HTTPS 时正常显示；
- `localhost` 上的 HTTP 允许开发测试；
- 其他 HTTP 地址显示高风险警告；
- 第一版不在服务端强制判断反向代理 TLS，以免错误拒绝已经在代理层终止 TLS 的请求。

## 7. 成功标准

- 开关、密码生成、轮换、关闭和宿主重启关闭符合定义；
- Windows Explorer 能完成基本列目录、新建目录、上传、下载、重命名和删除；
- macOS Finder 能完成基本连接和文件操作；
- Linux/macOS rclone mount 可读写；
- rclone sync 两个方向均可由用户主动运行；
- 大于 64 MiB 文件不被宿主完整缓存在内存；
- Range 读取、空目录、Unicode 文件名和稳定 Entry ID 正常；
- 关闭或轮换后旧密码立即失效；
- WebDAV 写入仍形成原子 PVLog 事务；
- 不扩展第三方应用文件系统权限；
- UI 明确说明它不是实时同步。

## 8. 非目标

V0.11 不做：

- 实时或后台自动同步；
- 双向同步、冲突副本或设备配对；
- SMB、SFTP、NFS；
- 多用户、每设备账号和权限目录；
- 分享链接和匿名访问；
- WebDAV 版本历史界面；
- Office 在线协作；
- 永久在线凭据；
- ZIP 浏览、回收站或标签同步；
- 专用 Windows/macOS/Linux 客户端。
