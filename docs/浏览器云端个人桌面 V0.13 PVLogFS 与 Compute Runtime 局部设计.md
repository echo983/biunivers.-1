# 浏览器云端个人桌面 V0.13 PVLogFS 与 Compute Runtime 局部设计

状态：已冻结

日期：2026-07-30

## 1. 已验证结论

2026-07-30 探针已证明：

- FUSE 只读树可以作为 `fuse-overlayfs` Lower；
- merged 可以 bind mount 到无 `/dev/fuse` 和 mount capability 的容器；
- 真实 revision 88 HEAD 可以在约 175 ms 内构造 27 Entry 的固定索引；
- 1.47 GB Manifest 文件可以不整文件物化而随机读取；
- whiteout 为同名字符设备，opaque directory 为
  `user.fuseoverlayfs.opaque=y`；
- 正常与 TERM 路径可以清理 mount、进程、容器和临时目录。

因此正式路线固定使用 `fuse-overlayfs`，V0.13 不再同时实现内核 OverlayFS 路线。

## 2. 进程与信任边界

```text
Biunivers Host
├── Workspace Service
├── 固定 HEAD Snapshot Provider
└── Verified Content Gateway
          │ 本机、逐 Run capability
          v
Compute Runtime Daemon
├── PVLogFS Supervisor
├── fuse-overlayfs Manager
└── OCI Adapter
          │ bind mount merged
          v
Executor Container
```

- Host 持有 RefStore 与 S3 凭据；
- Runtime 不持有 S3 凭据、管理员令牌和任意 Ref 访问能力；
- Runtime 只领取某个 Run 的固定快照与内容 capability；
- Executor 只见 `/workspace`，不能访问 Gateway；
- Host 主容器不挂 Docker socket；
- Runtime Daemon 是唯一可调用 OCI runtime 的组件。

探针中的通用 JSON/Unix socket 只验证边界可行性。正式 API 使用本机 Unix socket、长度前缀
消息、peer credential 校验和逐 Run 随机 capability，不把探针 JSON 协议升级为公共协议。

## 3. 固定 Snapshot

Run 创建时 Host 返回不可变描述：

```text
runId
workspaceId
refId（只在 Host/Runtime 内部）
inputHeadFid
revision
rootEntryId
entries[]
contentCapability
expiresAt
```

Host 必须在构造 EntryIndex 前后读取 Ref；Head 或 revision 变化则失败重试。Snapshot 发布后
不再跟随 Workspace Ref。

Runtime 不接受调用者自行提供 Head FID。它只接受 Host 为既有 Run 签发的准备请求。

## 4. inode 与文件语义

- 根 inode 固定为 1；
- 其余 Entry 按 Entry ID 原始 bytes 排序后依次分配 2..N；
- 同一固定 Head 每次挂载得到相同 inode；
- EntryIndex 中不得出现循环、孤儿、重复 Entry ID 或同目录重名；
- 普通目录呈现 `0755`，普通文件呈现 `0644`，整个 Lower mount 为只读；
- mtime 来自 PVLog Entry；
- 不支持 symlink、hardlink 语义、device、FIFO、socket、ACL、xattr 和 flock；
- 不支持的操作返回明确错误，不伪造成功。

第一版 FUSE 方法仅含 `lookup/getattr/readdir/open/read/statfs`。所有修改由 merged 的 Upper
承担。

## 5. 内容读取与完整性

PVLog 当前的 FID 是整个 Chunk 的 XXH3-128。仅取得 Chunk 的局部 S3 Range 时，客户端无法
重新计算整个 Chunk FID。

因此正式 PVLogFS 使用“完整 Chunk 验证缓存”：

1. 读取并验证 Head、Checkpoint、Manifest；
2. 首次访问某 Chunk 时完整 GET 该 Chunk；
3. 校验长度与 XXH3-128 FID；
4. 原子写入本地共享 cache；
5. 后续 `pread` 从已验证 cache 返回所需区间。

结果：

- 不会因打开 Workspace 下载完整大文件；
- 一次随机读取最多新下载一个 64 MiB Chunk；
- 同 FID Chunk 可跨 Workspace/Run 共享；
- 损坏或不完整 cache 文件直接丢弃并重新获取；
- Cache 不是权威数据，可按容量 LRU 回收。

探针中的小范围 S3 Range 证明了随机读取通路与跨分片定位，但只校验 Range 元数据和长度，
不作为完整 Chunk FID 校验证明。V0.13 不引入 Merkle 子块或新内容格式。

## 6. 挂载布局

```text
/run/biunivers/workspaces/<run-id>/
├── lower/
├── upper/
├── work/
├── merged/
└── runtime.json
```

- 目录由 Runtime 创建，owner/mode 固定，不接受外部路径；
- Lower 使用 PVLogFS，只读；
- COW 固定使用 `fuse-overlayfs`；
- `upper` 与 `work` 必须位于同一宿主文件系统；
- `/etc/fuse.conf` 必须启用 `user_allow_other`；
- Lower 和 merged 仅向 Runtime/OCI 所需主体开放；
- Executor 不获得 `/dev/fuse`。

清理顺序固定为：

```text
stop/kill container
→ unmount merged
→ stop fuse-overlayfs
→ unmount lower
→ stop PVLogFS
→ 按策略保留或删除 Upper
→ 删除其余 Run 目录
```

## 7. Runtime 窄 API

第一版仅提供：

```text
prepare(runId, snapshotCapability, resourcePolicy)
start(runId, executorId)
inspect(runId)
stop(runId, graceMs)
freeze(runId)
thaw(runId)
destroy(runId, preserveUpper)
```

不提供：

- 任意镜像名；
- 任意命令、mount、device、network 或 environment；
- Docker API 透传；
- 任意宿主路径；
- 任意 Ref/HEAD；
- 容器 exec shell。

`executorId` 在 Runtime 本地注册表中映射到固定 image digest、entrypoint 和资源上限。

## 8. Executor 沙箱

- 非 root UID/GID；
- image 使用固定 digest；
- root filesystem 只读；
- 仅 `/workspace` 可写；
- `--network none`；
- `--cap-drop ALL`；
- `no-new-privileges`；
- 不挂宿主 `/data`、secret、socket、device；
- 限制 CPU、内存、PID、运行时长和 Upper 容量；
- stdout/stderr 限量收集；
- OOM、超时和非零退出只改变 Run 状态，不自动提交。

V0.13 诊断执行器由系统维护，不开放第三方 OCI 安装。

## 9. 可观测与恢复

每个 Run 至少记录：

- snapshot/EntryIndex 加载时间和 Entry 数；
- FUSE lookup/read 次数与错误；
- Chunk cache hit/miss、下载 bytes、FID 失败；
- mount 和容器各阶段耗时；
- container exit/OOM/timeout；
- Upper bytes/inodes；
- 清理结果。

Runtime 启动时只扫描固定 Run 根目录。未知目录进入 quarantine；不得根据目录名直接恢复
数据库状态，也不得递归操作根目录之外的路径。
