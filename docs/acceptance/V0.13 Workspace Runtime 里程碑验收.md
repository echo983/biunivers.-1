# V0.13 Workspace Runtime 里程碑验收

状态：通过

日期：2026-07-31

范围：V0.13 Workspace Runtime 系统底座。第三方 Workspace App 协议、通用执行器安装、
网络与 secret 策略不在本版本范围。

## 1. Workspace 与固定快照

- [x] 文件管理器同父目录选择集可派生独立 Workspace；
- [x] 新虚拟根、新 lineage 和新 Entry ID，不泄漏 main 身份；
- [x] 普通文件复用不可变 Content FID，不复制内容；
- [x] Workspace 具备独立 Ref、baseline、revision、保留策略和单写租约；
- [x] 系统 Workspace 应用可列表、浏览、保留和删除；
- [x] 第三方 API 不接受任意 Ref，也不能遍历 Workspace。

## 2. PVLogFS 与隔离运行

- [x] 正式 Rust PVLogFS 挂载固定 Head；
- [x] 目录枚举、冷/热缓存读取、损坏缓存恢复和只读保护通过；
- [x] 64 MiB + 1 byte 跨分片内容按需读取并校验；
- [x] fuse-overlayfs 提供 COW merged 视图；
- [x] OCI 执行器以非 root UID/GID、无网络、零 capabilities、只读 rootfs 运行；
- [x] Workspace 可写只发生在受控 Upper；
- [x] 容器、Lower、merged 和缓存生命周期由独立 Compute Runtime 管理。

## 3. 提交与恢复

- [x] Upper 扫描、whiteout/opaque 解释和目标树投影失败关闭；
- [x] 新内容流式分片、XXH3-128 FID 与不可变对象回读验证；
- [x] 一个批处理 revision 原子发布 Workspace 新 Head；
- [x] no-op 不制造 revision；
- [x] CAS 冲突不覆盖赢家并保留 Upper；
- [x] daemon 强制终止后清理容器与挂载、保留 Upper、保持 Ref 不变并释放租约；
- [x] 中断恢复对 PREPARING、RUNNING、STOPPED、COMMITTING 使用确定性状态规则；
- [x] RefStore 备份恢复完整保留 Workspace Ref、baseline、Run、租约与 GC roots。

## 4. Diff 与导回

- [x] baseline/current 结构化增删改 Diff；
- [x] 小文本按需统一 Diff，二进制和超限文件明确拒绝；
- [x] 选择新增/修改结果，删除不传播；
- [x] main 目标目录由用户显式选择；
- [x] 同名可取消整批或安全自动改名，不提供覆盖；
- [x] Content FID 复用、新 Entry ID、main 单 revision 原子导回；
- [x] Workspace/main revision 竞态不产生半批结果。

真实 Docker/S3/持久 RefStore 界面验收：

```text
多选新增目录 + 冲突文件：通过
目标目录导航：通过
递归目录及 result.txt：通过
原 32 B 文件与导回 35 B 文件并存：通过
自动插入 (Workspace) 后缀且不覆盖：通过
```

## 5. 不可变存储与 GC

- [x] 对象后端继续只依赖 S3 GET/HEAD/PUT；
- [x] Workspace Head、Snapshot、Run input/output Head 均作为 GC roots；
- [x] GC 仍为只读报告，`deletionAllowed=false`；
- [x] 提交或上传失败产生的不可变孤儿不会使 Ref 指向不完整状态；
- [x] V0.13 不启用对象删除。

## 6. 版本边界

V0.13 使用系统维护的 digest-pinned 诊断执行器证明 Runtime 闭环。它不宣称第三方可以安装
任意 Workspace App，也不把 Docker socket、宿主路径、任意网络或 secret 暴露给 iframe。
这些能力必须在后续 `biunivers.workspace-app/1` 设计中单独评审。
