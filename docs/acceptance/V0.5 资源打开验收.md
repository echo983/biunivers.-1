## 3. 真实环境结果

以下场景已通过：

1. 从公开 GitHub 仓库安装带 Handler 的 Notepad；
2. 文件管理器双击 TXT，自动交付 Launch Context 并读取正确内容；
3. 编辑、覆盖保存、关闭和重新打开后内容持久存在；
4. 普通启动 Notepad，新建并另存为 TXT；
5. 第二个 TXT 复用已有窗口；
6. 有未保存内容时，取消切换保留原内容，确认切换放弃原内容；
7. 文件重命名和移动后仍能解析 Handler、打开并读取原内容；
8. 设置 `.txt · edit` 默认关联并在应用管理中正确展示；
9. 停用或卸载 Notepad 后 Handler 立即失效；
10. 重新启用或重新安装后 Handler 恢复；
11. 容器重启后文件、应用记录、关联和打开链路保持正常。

旧句柄覆盖与 `FILE_VERSION_CONFLICT` 已在 File Service V0.1 真实验收中通过；Open Resource
签发的 handle 复用同一 Host API 写入与 expected-version 路径。

- React loading 生命周期 lint 问题：`82705da` 清理，最终 lint 通过。
