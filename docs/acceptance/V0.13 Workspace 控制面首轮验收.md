状态：通过

## 1. Schema 与迁移

- [x] 新数据库直接创建 Schema v2；
- [x] Schema v1 在 `BEGIN IMMEDIATE` 中迁移到 v2；
- [x] 迁移中途失败回滚新表、meta 与 `user_version`；
- [x] 未知未来版本拒绝打开且不改写；
- [x] Workspace/Run 表使用 STRICT、CHECK 与 FK；
- [x] 原有 Ref、Snapshot 和 main 数据保持不变。


## 2. Workspace 与 Run

- [x] Workspace + `ws-*` Ref 原子创建；
- [x] 来源 Head 变化时整体回滚；
- [x] Workspace、Ref、Run 备份恢复；
- [x] 无活动 Run 时 Workspace + 历史 Run + Snapshot + Ref 原子删除；
- [x] PREPARING 创建与写租约原子提交；
- [x] 同一 Workspace 第二个写 Run 被拒绝；
- [x] RUNNING、STOPPED、COMMITTING 持续占用租约；
- [x] FAILED、DISCARDED、CONFLICT、COMMITTED 释放租约；
- [x] 非法、陈旧和时间倒退状态迁移整体拒绝；
- [x] Ref CAS、COMMITTED/CONFLICT、outputHead 和租约释放原子提交；
- [x] CAS 失败不覆盖赢家。

## 3. Ref-aware 与 GC

- [x] EntryIndex 必须显式接收 `refId`；
- [x] FileSystemTransactions 必须显式接收 `refId`；
- [x] 两个 Ref 可独立发布，Workspace 变化不改变 main；
- [x] internal File Manager 由组装层固定 `appId + refId`；
- [x] File Host、Resource Session、Wormhole 和桌面明确绑定 main；
- [x] public/third-party API 未增加 Ref 参数；
- [x] GC 保护全部 Ref、Snapshot 和 Run input/output Head；
- [x] 独立 lineage Workspace 对象图不会被报告为候选。
