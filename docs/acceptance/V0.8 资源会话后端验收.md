## 保存推进与冲突

创建临时待保存 `.txt` 会话：

1. 第一次完整 PUT 创建 revision 35；
2. 同一会话第二次 PUT 前进到 revision 36 和新的 `contentVersion`；
3. 在第一次保存后签发的第二个 edit 会话尝试覆盖，返回 409；
4. 原会话读回内容为第二次保存内容，旧会话没有覆盖成功；
5. 临时文件目录项删除成功，形成 revision 37。

这验证了待保存会话、同会话版本推进、预期内容版本与 Ref CAS 冲突闭环。

## 真实 64 MiB 分块边界

通过 Resource Session PUT 写入一个 `64 MiB + 1` 的临时文件：

```text
size: 67108865
revision: 38
```

随后读取：

```http
Range: bytes=67108860-67108864
```

结果：

```text
HTTP/1.1 206 Partial Content
Accept-Ranges: bytes
Content-Length: 5
Content-Range: bytes 67108860-67108864/67108865
```

实际响应体为 5 字节，证明跨 Manifest Chunk 边界的请求没有退化为向客户端返回完整文件。
临时文件目录项已删除。底层不可变测试对象按一次刻录语义保留，等待未来 GC 策略处理。

## 真实租约过期

签发会话后保持 305 秒无 GET、metadata 或 renew：

```text
after305SecondsGet=410
renewed=[]
rejected[0].code=RESOURCE_SESSION_NOT_FOUND
```

会话在 300 秒硬过期点后不能读取；首次过期读取清理会话，后续 renew 不能使其复活。
