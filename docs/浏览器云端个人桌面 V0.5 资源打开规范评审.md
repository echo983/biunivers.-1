# 浏览器云端个人桌面 V0.5 资源打开规范评审

状态：评审通过

评审日期：2026-07-29

评审对象：[V0.5 资源打开设计](<浏览器云端个人桌面 V0.5 资源打开设计.md>)

## 1. 结论

设计闭环、必要且可实施。采用“应用自报 Handler、宿主管理候选、用户管理默认关联、每次
打开重新签发窗口级 capability”的混合路线。

V0.5 只完成 `.txt` → 第三方记事本的纵向闭环。Handler 声明与 Launch Context 统一放入
一个可选的 `biunivers.open-resource/1` 协议，文件读写继续复用 `biunivers.host-api/1`。

该方案不修改已冻结的 Static App Protocol v1、App Manifest v1 或 Host API v1，不增加
PVLogS3Lite 对象格式，也不把 File Service 内部标识暴露给应用。

## 2. 必要性审查

以下部分是双击打开第三方应用不可缺少的：

- 应用声明可以处理的扩展名；
- 安装器校验和登记候选处理器；
- 宿主选择默认应用或显示打开方式；
- 目标窗口专属的 Launch Context；
- 为目标窗口重新签发文件句柄；
- 应用停用、更新和卸载时使候选安全失效。

以下部分对第一版价值低，已排除：

- 内容嗅探和魔数；
- Handler 自定义入口、命令行和 URL scheme；
- 多文件、拖放、后台调用和资源管道；
- 视频 Range/Seek；
- 应用市场推荐；
- 多用户和跨设备默认关联同步。

## 3. 七项冻结决策

### D1：协议名称和交付文件

- 协议标识：`biunivers.open-resource/1`；
- 协议原文：`BIUNIVERS_OPEN_RESOURCE_PROTOCOL_V1.md`；
- Handler 声明：`biunivers.open-resource.json`；
- Schema：`biunivers.open-resource.schema.json`，供开发者和宿主实现校验。

使用扩展协议的应用必须携带前两项；Schema 不要求放入应用仓库。

### D2：一个协议包含声明和运行时上下文

Handler 包元数据与 `launch.getContext` 使用同一个版本协议，避免为一个最小闭环拆出多个
相互依赖的小协议。文件内容操作不并入该协议，继续使用 Host API v1。

### D3：`open` 与 `edit`

- `open`：消费资源，不承诺修改原资源；
- `edit`：应用能够修改并保存回原资源。

文件管理器双击优先请求 `edit`；没有 edit 候选时回退到 `open`。实际句柄权限仍取多个约束
的交集，声明 edit 不保证得到写权限。

### D4：唯一候选直接打开

有效候选只有一个时直接打开；多个候选才显示打开方式。用户始终可以通过后续“打开方式”
入口覆盖选择。

### D5：默认关联先使用浏览器桌面状态

V0.5 默认关联保存在现有桌面持久化状态，避免引入服务端用户设置模型。候选 Handler 仍由
服务端安装记录提供。未来迁移到用户配置服务不改变第三方协议。

### D6：Launch Context 生命周期

每个 Launch Context：

- 绑定目标 app、origin 和 window instance；
- 只能由该实例通过 `launch.getContext` 领取；
- 首次成功领取后即消费；
- 未领取时 5 分钟过期；
- 窗口关闭时撤销；
- 不放入 URL、公开配置或日志。

当前桌面每个 appId 只有一个窗口。目标应用已经运行时，宿主给该窗口建立新的待领取上下文，
并发送不含资源信息的 `launch.contextAvailable` 通知；应用再次领取并自行处理未保存内容。
一个窗口同一时刻最多有一个未领取上下文，不能静默覆盖。

其中的文件 handle 使用 Host API 既有过期、释放和窗口关闭撤销规则。

### D7：失效默认偏好

应用停用、卸载或更新后不再声明对应 Handler 时，默认关联记录可以保留，但必须视为失效且
不能启动应用。相同 appId 和 handlerId 日后恢复有效时，旧偏好可重新生效。

这使停用和临时更新可逆，同时不会产生悬空授权。

## 4. 评审修正

相较初稿作出以下收敛：

- V1 每个 Handler 至少声明一个扩展名；媒体类型只能辅助匹配；
- `mediaTypes` 可选而不是必需空数组；
- V1 一个 Launch Context 恰好包含一个资源，不用数组伪装已支持批量；
- V1 适配当前单实例窗口模型，通过空载荷通知领取后续上下文，不引入多窗口重构；
- 文件管理器双击优先 edit、再回退 open；
- 默认关联按 `extension + action` 区分，避免只读查看器抢占编辑关联；
- Handler 声明最大权限，但不决定实际句柄权限；
- 不在 V1 定义通用应用 A → 应用 B API，只保留宿主重新签发原则。

## 5. 实施前门槛

进入功能施工前必须具备：

- 冻结的协议原文；
- 严格 JSON Schema 与有效/无效样例；
- 安装记录的兼容迁移方案；
- Launch Context 服务端状态与撤销模型；
- 文件管理器、桌面窗口系统、Host API 的责任分界；
- 主仓库与 `biunivers-notepad` 的分阶段验收计划。
