# 浏览器云端个人桌面 V0.14 Runtime Proxy、网络与 iframe 规范评审

日期：2026-07-31  
评审对象：《浏览器云端个人桌面 V0.14 Runtime Proxy、网络与 iframe 局部设计》  
结论：**逻辑闭环，可以按最小施工顺序推进。**

## 1. 必要性结论

以下能力不可删：

- 稳定 Instance origin：否则重建会改变 URL，或不同 Instance 共享浏览器状态；
- 单次 bootstrap 与 HttpOnly 会话：否则稳定且可猜的 URL 等于公开入口；
- 专用 bridge 且不 publish：否则 BWA 绕过 Manager 暴露到宿主/LAN；
- Runtime 窄 endpoint 查询：Manager 不应获得 Docker socket；
- HTTP 流式/Range/WebSocket：这是通用 Web 应用和媒体/智能体 UI 的基础能力；
- 宿主故障页：BWA 停止时自身无法显示控制界面；
- internal Manager：系统必须能管理一个尚未启动或已经崩溃的应用。

## 2. 已删减的过度设计

设计明确不做：

- OAuth/OIDC、多用户 RBAC 与外部公开 ingress；
- Service Mesh、容器 DNS 服务发现和负载均衡；
- HTML/CSP/绝对 URL 自动重写；
- WebSocket 消息协议理解和自动重连；
- 逐应用出站域名或私网 ACL；
- ready postMessage、主题、菜单和窗口控制协议；
- Docker/Compose 参数编辑器、shell 与日志终端；
- 通用自动重启和调度器。

这些能力不是第一版用户闭环的前提，加入会扩大攻击面和状态空间。

## 3. 自洽性检查

### 身份

Application repository、Instance ID、Run ID 和 Container ID 分层清楚。浏览器只看稳定
Instance origin；Proxy 每次把它解析到当前 Run，避免把临时执行身份持久化为用户入口。

### 授权

Instance ID 只用于路由，不授予访问。Desktop 同源控制面签发一次性 ticket，BWA origin
消费后使用 HttpOnly 会话；WebSocket 与 HTTP 使用同一授权根。

### 网络

容器有普通出站能力，但无 published port、host network 或 Docker socket。Manager 只能通过
Runtime 返回的固定网络 endpoint 入站访问，符合既定信任定位。

### 生命周期

iframe 关闭不停止容器；Instance 停止会撤销 endpoint，但浏览器会话可用于恢复后刷新。
保存重启只替换 Run，不改变 origin。异常 Upper 仍由 V0.14-B 门禁控制。

### 失败

导航与 API 错误分开处理，避免向 Range/媒体请求返回 HTML。所有故障映射都不泄露执行面
细节。连接失败只使 endpoint 缓存失效，不自动提交或重启。

## 4. 施工风险

1. Docker bridge IP 的宿主可达性是 Linux 基线，必须以 adapter 隔离平台差异。
2. Node 原生 HTTP 代理必须正确处理 backpressure、abort 和 hop-by-hop headers。
3. WebSocket upgrade 必须在任何上游连接前完成 Host 与 Cookie 校验。
4. bootstrap query ticket 必须 no-store、单次消费且不进入日志。
5. upstream Cookie 必须防止覆盖 `__Host-biunivers-` 保留前缀。

这些风险均有窄测试边界，不要求引入大型代理框架。

## 5. 施工门

第一纵向切片只实现：

```text
origin label
→ ticket/session
→ 固定测试 endpoint
→ GET /health 与 GET /
→ 未授权/停止/连接失败映射
```

该切片通过后再加入 Docker bridge endpoint、流式 HTTP、WebSocket 和最终 UI。这样能先验证
身份与授权根，避免网络细节掩盖访问控制错误。
