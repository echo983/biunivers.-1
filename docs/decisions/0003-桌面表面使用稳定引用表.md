# ADR-0003：桌面表面使用稳定引用表

状态：已接受

日期：2026-07-29

适用范围：V0.7 及后续桌面项目管理

## 背景

当前桌面图标只是 `AppDefinition.desktop === true` 的投影，不能独立增删、定位或持久化布局。
完整桌面需要同时放置应用、文件、目录，并为未来标签聚合等动态视图保留扩展位置。

把桌面实现为 File Service 中的真实目录会迫使应用快捷方式和动态视图伪装成文件；使用
`.lnk`、`.desktop` 或符号链接又会把宿主对象模型泄漏到文件协议。

## 决策

桌面是宿主维护的引用表，不是文件夹，也不产生快捷方式文件。

每个桌面项目包含：

- 独立、稳定的桌面项目 ID；
- 目标类型；
- 由对应 Resolver 解释的不透明长期 handle；
- 逻辑像素位置；
- 创建时间等宿主管理元数据。

第一版内建目标类型：

| 类型 | handle | Resolver |
|---|---|---|
| `app` | `appId` | 当前 App 表 |
| `file` | File Service `Entry ID` | 当前文件 Entry |
| `directory` | File Service `Entry ID` | 当前目录 Entry |

目标类型在架构上可扩展，但 Resolver 只能由宿主显式注册。第三方应用不能仅凭声明添加新类型、
解析任意 handle 或获得宿主权限。未来动态视图可以增加 `view` 类型，其 handle 指向独立
Saved View Registry；本 ADR 不提前定义标签查询格式。

桌面 handle 是长期定位引用，不是 Host API capability。双击文件仍必须经过 Open Resource
Handler 解析、用户关联和窗口级临时 capability 签发。

## 生命周期语义

- “添加到桌面”创建引用，不移动或复制目标；
- “从桌面移除”只删除引用，不卸载应用、不删除文件；
- 文件或目录重命名、移动后，由稳定 Entry ID 解析当前名称和类型；
- Entry 被移除、应用被停用或卸载后，桌面项目保留为失效引用；
- 同一目标在一个桌面表面中默认只允许一个项目；
- 目标以同一稳定 ID 恢复后，失效项目可以恢复正常。

## 持久化边界

桌面引用和布局属于宿主可变 UI 状态，存入独立 Desktop Surface Service，不进入 PVLog，
不写入第三方应用仓库，也不只保存在浏览器 localStorage。

```text
PVLog / RefStore       文件事实与当前文件树
APP 表                 应用安装与状态
Desktop Surface        用户入口引用与布局
Host capability        一次用户动作产生的短期访问权限
```

Desktop Surface 使用 revision/CAS，使添加、移除和成组移动能够原子提交，并能检测多标签页
竞争。

## 影响

正面影响：

- 应用、文件、目录和未来视图使用统一桌面模型；
- 不污染文件系统；
- 文件移动和重命名不破坏桌面入口；
- 布局可以跨浏览器和容器重启恢复；
- 长期引用与短期权限保持分离。

代价：

- 需要新的小型持久化服务和 Resolver 层；
- 文件管理器和 App 菜单需要“添加到桌面”入口；
- 失效引用需要明确 UI；
- 目录打开需要 internal 导航上下文。

## 非目标

本决策不定义：

- 任意第三方 Resolver 注册；
- 标签或搜索查询语言；
- 快捷方式文件交换格式；
- 多用户共享桌面；
- 多桌面、工作区或多显示器布局。
