# 浏览器云端个人桌面 V0.13 Workspace Runtime 施工计划

状态：施工中

日期：2026-07-30

## 1. 施工原则

- 先使 File Service 内部 Ref-aware，再增加 Workspace；
- public/third-party API 不暴露任意 Ref；
- 先完成不依赖 Runtime 的创建、浏览和删除；
- Runtime、COW 提交、导回分别设验收门；
- 无法证明的 Upper 变化一律拒绝提交并保留现场；
- 每个切片独立提交、全量回归并同步文档。

## 2. 切片 A：RefStore Schema v2

状态：已完成（2026-07-30）

实现：

- Schema v1 → v2 显式事务迁移；
- `workspace_records`、`workspace_runs`；
- Workspace + Ref 原子创建/删除；
- Run 状态迁移和 `active_write_run_id`；
- `listRefs()` 与活动 Run 临时 roots；
- 备份恢复覆盖新表。

测试：

- 全新初始化、v1 迁移和迁移失败回滚；
- 非法状态迁移与同 Workspace 双写拒绝；
- 活动 Workspace 删除拒绝；
- backup/restore 后 Ref、Workspace、Run 一致；
- 原有 main Ref/CAS/Snapshot 全部通过。

出口：没有 Workspace 时，现有系统行为与 V0.12 一致。

## 3. 切片 B：内部 Ref-aware File Service

状态：已完成（2026-07-30）

实现：

- `loadEntryIndex(..., refId)`；
- `FileSystemTransactions({ refId })`；
- 内部文件浏览接受受信任 Ref scope；
- main 组装层显式传 `main`；
- GC 扫描全部 Ref 和活动 Run roots。

禁止 public HTTP、Host API、Resource Session 或 Wormhole 接受 `refId`。

测试两个 Ref 隔离读写、main 全量回归、GC 多 Ref 可达性和非内部 Ref 选择拒绝。

出口：Ref-aware 是内部能力，授权面不扩大。

## 4. 切片 C：选择集派生

状态：已完成（2026-07-30）

实现 `WorkspaceDeriver`：

- 固定 main `sourceHead`；
- 校验同一父目录并递归展开；
- 限制深度、Entry 数和元数据；
- 新虚拟根、lineage 和 Entry ID；
- 复用 Content FID；
- revision 0 Checkpoint/Genesis Head；
- 原子创建 Workspace + `ws-*` Ref。

测试文件、目录、空目录、嵌套、重名、越界、来源竞争和 SQLite 失败。确认未选内容不可见、
Entry ID 全新而 Content FID 复用。

出口：服务层可创建和删除最小 Workspace，不依赖 Docker。

完成说明：

- 新增窄幅 PVLog Core ABI，由 Rust 核心从 packed Entry 投影规范编码带内容的 revision 0
  Checkpoint；TypeScript 不复制 CBOR 格式；
- `WorkspaceDeriver` 固定读取 `main` HEAD，要求非空、唯一且同一直接父目录的选择集，目录递归
  展开；
- 默认限制 100 个直接选择、100,000 个派生 Entry、128 层深度和 32 MiB packed 元数据；
- Workspace 使用新虚拟根、新 lineage 和全新 Entry ID，文件 Content FID 与大小原样复用；
- Checkpoint 与 Genesis Head 先写不可变仓库，再由 RefStore 在单一 SQLite 事务中校验来源 HEAD
  并原子发布 Workspace + `ws-*` Ref；
- 来源竞争会返回 `REF_CONFLICT`，不留下 Workspace/Ref；已写的不可变对象允许成为未来 GC
  候选，不执行危险回滚删除；
- 服务测试覆盖文件与嵌套目录派生、未选择隔离、FID 复用、同父约束、重复选择、Entry/深度/
  元数据边界和发布前来源竞争。

## 5. 切片 D：Workspace 系统应用

状态：已完成并通过用户验收（2026-07-30）

文件管理器增加“创建工作空间”。新增 internal Workspace 应用：

- Workspace 列表与来源；
- Ref-aware 只读文件浏览；
- retention 与删除；
- Run 占位区域。

复用现有 FileManager Browser，不复制第二套文件浏览器。

用户验收创建、内容隔离、无重复上传、删除不影响 main、刷新和宿主重启。

出口：Workspace 在不运行容器时也是完整可管理对象。

完成说明：

- 文件管理器工具栏增加“创建工作空间”，直接使用当前目录选择集并由服务端重新执行同父目录
  校验；
- 新增 `system.workspaces` internal 系统应用，提供 Workspace 列表、来源与 revision、只读目录
  浏览、临时/保留切换和安全删除；
- 创建权限只授予 `system.files`，管理与 Workspace Ref 浏览权限只授予
  `system.workspaces`；第三方应用不能调用，也不能提交任意 `refId`；
- Workspace 只读浏览使用专用 internal 路由，现有 Host API、Resource Session、Wormhole 和
  public 文件选择器仍固定 main；
- 删除继续由 RefStore 原子删除 Workspace/Run/Snapshot/Ref 控制面记录，活动写 Run 存在时
  拒绝；
- 新增 `scripts/run-workspace-product-test.sh`，用于保留现有数据卷的容器人工验收。

用户验收结果：

- 文件管理器选择集创建和 Workspace 管理入口符合预期；
- 只读目录浏览、深层目录导航和面包屑符合预期；
- 长文件名布局符合预期；
- 双击文件会明确提示当前阶段的只读目录浏览边界，不误发 main 文件授权；
- Slice D 人工验收门通过。

## 6. 切片 E：正式 PVLogFS 与 Verified Chunk Cache

状态：已完成并通过用户验收（2026-07-30）

实现：

- 固定 Snapshot、稳定 inode、只读 FUSE；
- 完整 Chunk GET + XXH3 校验；
- 原子 cache、同 FID 并发合并；
- LRU、损坏恢复和指标。

基准覆盖 1,000/10,000 小文件、64 MiB 边界、1 GiB Manifest、冷/热/损坏 cache。

出口：不全量物化；所有返回内容来自已验证 Chunk；小文件元数据操作不逐次访问
Host/SQLite。

阶段进度：

- `WorkspaceSnapshotProvider` 已固定 Workspace Ref 的前后 HEAD/revision，竞争时拒绝发布 Snapshot；
- 根 inode 固定为 1，其余 Entry 严格按 Entry ID bytes 排序稳定分配；
- `VerifiedChunkCache` 已实现完整 Chunk GET、长度与 XXH3-128 校验、原子落盘、同 FID
  并发合并、重启复验、同长度损坏恢复和容量 LRU；
- `WorkspaceContentReader` 已实现 Chunk/Manifest 统一随机读、64 MiB 跨分片定位和单请求
  1 MiB 上限；
- `PvlogFsGateway` 已将固定 Snapshot 与读取能力封装为 `0600` Unix socket、256-bit
  capability 和长度前缀二进制帧；不再沿用探针 JSON/base64 读取协议；
- 正式 `crates/pvlogfs` 已实现 `lookup/getattr/readdir/open/read/statfs`、只读权限、稳定 inode、
  固定 Snapshot 校验和 Gateway 二进制读取；实验 crate 继续保留为历史探针；
- `scripts/run-pvlogfs-test.sh` 已覆盖真实数据卷、固定 Workspace、FUSE 挂载、目录/inode
  枚举、验证缓存读取和只读拒绝；
- 测试已覆盖 cache hit/miss、并发 miss、重启、损坏、LRU、小文件和 64 MiB 边界读取。

验收进度：

- Rust test/clippy、TypeScript lint/build 与服务测试已通过；
- 2026-07-30 用户在真实数据卷执行 `scripts/run-pvlogfs-test.sh`，成功固定 Workspace
  revision 0、挂载 8 Entry；
- 实测覆盖根与嵌套目录、稳定 inode、普通/空/中文名文件、验证缓存读取、写入拒绝、卸载和
  进程清理，全部通过；
- 1,000/10,000 小文件稳定 inode 投影分别约 1.64 ms / 18.30 ms；
- 逻辑 1 GiB Manifest 随机读与跨 64 MiB 边界读取通过；重复 Chunk 场景仅下载一个
  64 MiB Chunk，后续为 cache hit；
- 服务测试中的冷/热、同 FID 并发、重启复验、同长度损坏恢复和 LRU 全部通过；
- 真实挂载复验完成：3 次读取为 1 次冷 miss、2 次 hit；主动同长度破坏后检测到
  1 次 corruption，重新验证 100 bytes、重新下载 50 bytes 并恢复读取；
- 正式 PVLogFS、规模、逻辑 1 GiB、冷/热/损坏缓存和只读保护验收门全部关闭。

## 7. 切片 F：Compute Runtime Daemon

状态：下一步

实现本机认证窄 API、固定执行器注册表、Run 目录、PVLogFS/fuse-overlayfs supervisor、
OCI 生命周期、资源限制、orphan 隔离和幂等清理。

安全验收：

- 非 root、无网络/capabilities；
- 无 `/dev/fuse`、S3 secret、RefStore、Docker socket；
- 不能指定镜像、命令、mount、device 或宿主路径；
- 只见 `/workspace`；
- 重启对账不删除未知 Upper；
- Upper 超限稳定返回 ENOSPC。

出口：诊断执行器能修改 Upper，但尚不推进 Ref。

## 8. 切片 G：COW 提交

实现 freeze/stop、安全扫描、whiteout/opaque、支持类型矩阵、目标树、新内容分片、PVLog
对象、Ref CAS、Run 终态、写租约和 discard。

测试新建、覆盖、截断、删除、重命名、目录替换、未知 xattr、symlink、hardlink、特殊文件、
扫描竞争、CAS/S3/SQLite 故障。

出口：成功后新 Head 正确；任何失败都保持 Ref 不变并保留 Upper。

## 9. 切片 H：Diff 与导回

实现 baseline/current Diff、小文本 Diff、二进制元数据、选择结果、main 目标目录、冲突策略、
Content FID 复用和 main 原子批量复制。

用户验收部分导回、同名冲突、无半批结果、不传播 Workspace 删除、丢弃不影响已导回内容。

出口：完整主线闭环。

## 11. 分支策略

当前探针分支保存设计和实验。正式施工从最新主线依次建立：

```text
feature/workspace-control-v0.13
feature/workspace-product-v0.13
feature/workspace-runtime-v0.13
feature/workspace-commit-v0.13
```

每条分支进入下一条前合并，避免控制面、UI、Runtime 和提交器长期漂移。第一个施工提交只做
切片 A，不同时加入 UI 或 Docker。
