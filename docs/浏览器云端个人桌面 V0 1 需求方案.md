# 浏览器云端个人桌面 V0.1 需求方案

## 1. 文档用途

本方案用于与 Codex 讨论和实现浏览器云端个人桌面的第一版。

讨论和开发时应遵守以下原则：

1. 目标是尽快得到可部署、可日常使用的产物。
2. 优先复用现成组件，不自行开发窗口拖动和缩放引擎。
3. 不为尚未出现的需求设计完整操作系统抽象。
4. 第一版只支持单用户和可信应用。
5. 不扩大本需求中明确列出的功能范围。
6. 每完成一个阶段，都应保持项目可以运行和部署。
7. 遇到技术问题时，优先减少功能，而不是引入新的框架。

---

# 2. 产品定义

该产品是一个部署在个人 VPS 上、通过浏览器访问的个人桌面入口。

它提供：

* 桌面背景；
* 桌面应用图标；
* 底部任务栏；
* App 菜单；
* 多窗口显示；
* 应用启动、关闭、聚焦、隐藏和最大化；
* 对现有 Web 服务的 iframe 接入；
* 浏览器本地的桌面状态保存。

它不是完整操作系统，也不负责运行任意传统桌面软件。

第一版的主要价值是：

> 用一个统一的浏览器桌面，集中打开和管理用户已有的 Web 服务与少量内建工具。

典型接入对象包括：

* Transmission Web UI；
* File Browser；
* NAS 管理界面；
* 下载管理器；
* 笔记服务；
* 媒体服务；
* 路由器或服务器管理页面；
* 其他允许被 iframe 嵌入的自托管 Web 服务。

---

# 3. 第一版成功标准

第一版达到以下状态，即视为成功：

1. 用户可以通过一个网址打开桌面。
2. 桌面至少显示三个应用图标。
3. 用户可以从桌面图标或 App 菜单启动应用。
4. 应用在可拖动、可缩放的窗口中运行。
5. 用户可以同时打开多个不同应用。
6. 同一应用不会重复创建多个窗口。
7. 任务栏能够表示已经运行的应用。
8. 点击任务栏项目能够显示、隐藏或聚焦对应窗口。
9. 浏览器刷新后，固定应用、壁纸和窗口位置能够恢复。
10. 项目可以通过 Docker 构建并部署到 VPS。
11. 应用列表可以通过运行时 JSON 配置修改，不需要重新编译前端。

# 4. 第一版范围

## 4.1 必须实现

### 桌面层

* 全屏桌面容器；
* 桌面背景；
* 桌面图标网格；
* 图标名称；
* 双击图标启动应用；
* 桌面空白区域点击后关闭 App 菜单；
* 防止浏览器页面自身出现滚动条。

### 任务栏

* 固定在屏幕底部；
* App 菜单按钮；
* 固定应用区域；
* 运行中应用区域；
* 当前活动窗口标记；
* 隐藏窗口标记；
* 当前时间显示。

### App 菜单

* 点击任务栏按钮打开；
* 显示所有已注册应用；
* 根据名称搜索应用；
* 点击应用后启动并关闭菜单；
* 点击菜单外区域关闭；
* 按 Escape 关闭。

### 窗口管理

* 创建窗口；
* 关闭窗口；
* 拖动窗口；
* 调整窗口尺寸；
* 点击窗口后置于前台；
* 最大化；
* 从最大化状态恢复；
* 通过任务栏隐藏窗口；
* 通过任务栏重新显示窗口；
* 浏览器尺寸改变后，窗口不能完全移出可视区域；
* 窗口不能覆盖底部任务栏区域。

### 应用接入

第一版仅支持三种应用类型：

1. `internal`

   * React 内建组件；
   * 用于设置、关于等系统应用。

2. `iframe`

   * 在窗口中打开可信的 Web 服务；
   * 适合自托管应用和同源反向代理服务。

3. `external`

   * 在浏览器新标签页打开；
   * 用于不能被 iframe 嵌入的网站。

### 状态保存

使用浏览器 `localStorage` 保存：

* 固定应用；
* 壁纸；
  -窗口坐标；
* 窗口尺寸；
* 上次打开的应用；
* 应用窗口是否隐藏；
* 应用窗口是否最大化。

# 5. 用户和运行环境

## 5.1 目标用户

第一版只面向一个个人用户。

默认条件：

* 用户拥有自己的 VPS 或家用服务器；
* 用户能够编辑 JSON 配置；
* 用户能够配置 Nginx、Caddy 或其他反向代理；
* 接入的 iframe 应用由用户信任；
* 不考虑公开互联网用户提交任意应用地址。

## 5.2 浏览器范围

第一版只需要支持：

* 当前稳定版 Chromium；
* 当前稳定版 Chrome；
* 当前稳定版 Edge。

Firefox 和 Safari 可以尽量兼容，但不作为第一版验收阻断条件。

## 5.3 屏幕范围

第一版只针对桌面设备：

* 最低视口宽度：1024px；
* 推荐宽度：1280px 以上；
* 鼠标和键盘作为主要输入设备。

当视口小于 1024px 时，显示提示：

> 当前版本建议使用桌面浏览器访问。

不需要为手机重新设计窗口交互。

# 7. 核心设计决策

## 7.1 一个应用最多一个窗口

V0.1 中所有应用均为单实例应用。

调用：

```ts
openApp("transmission");
```

时：

* 如果应用未运行，创建窗口；
* 如果应用已运行但被隐藏，显示并聚焦；
* 如果应用已运行且可见，直接聚焦；
* 不创建第二个实例。

这样可以避免：

* 窗口分组；
* 应用进程和窗口实例分离；
* 多实例标题处理；
* 任务栏多窗口选择器；
* 重复 iframe 消耗。

---

## 7.2 任务栏隐藏代替 WinBox 原生最小化

WinBox 原生最小化界面可能与自定义任务栏重复。

因此第一版规定：

* 隐藏 WinBox 原生最小化按钮；
* 隐藏 WinBox 全屏按钮；
* 保留最大化按钮；
* 保留关闭按钮；
* 任务栏点击使用 WinBox 的 `hide()` 和 `show()`；
* 产品内部将这一状态称为“最小化”，实现上使用隐藏。

窗口创建时加入：

```ts
class: ["no-min", "no-full"]
```

任务栏行为：

```ts
if (window.hidden) {
  window.show();
  window.focus();
} else if (window.active) {
  window.hide();
} else {
  window.focus();
}
```

---

## 7.3 WinBox 是机械状态源，Zustand 是产品状态源

WinBox 内部管理实时窗口 DOM 和动画。

Zustand 保存：

* 窗口对应哪个应用；
* 窗口是否存在；
* 是否隐藏；
* 是否最大化；
* 是否活动；
* 最终坐标；
* 最终尺寸。

拖动和缩放过程中，不要求每一帧写入 Zustand。

使用 WinBox 的回调获得最终状态，并防抖保存：

* `onmove`；
* `onresize`；
* `onfocus`；
* `onblur`；
* `onhide`；
* `onshow`；
* `onmaximize`；
* `onrestore`；
* `onclose`。

持久化防抖建议为 200—500 毫秒。

---

## 7.4 React 内容直接挂载进 WinBox

每个窗口创建一个独立 DOM 容器和 React Root。

概念代码：

```ts
const container = document.createElement("div");
container.className = "app-window-root";

const reactRoot = createRoot(container);

const winbox = new WinBox({
  title: app.name,
  icon: app.icon,
  root: desktopWindowLayer,
  mount: container
});

reactRoot.render(<AppRenderer app={app} />);
```

关闭窗口时必须：

1. 从运行窗口状态中删除；
2. 调用 `reactRoot.unmount()`；
3. 删除保存的运行态；
4. 允许 WinBox 销毁窗口 DOM；
5. 清理窗口实例映射。

不能只关闭 WinBox 而不卸载 React Root。

---

## 7.5 窗口实例不写入持久化状态

WinBox 实例和 React Root 不能放入 localStorage。

内存中维护：

```ts
type WindowRuntime = {
  winbox: WinBox;
  reactRoot: Root;
};
```

```ts
const windowRuntimeMap = new Map<string, WindowRuntime>();
```

Zustand 中只保存可序列化状态。

# 8. 应用注册表

## 8.1 运行时配置

应用注册表从以下地址加载：

```text
/config/apps.json
```

该文件在运行时通过 `fetch` 读取。

修改应用配置后，不需要重新构建前端。

如果配置读取失败：

* 显示内建系统应用；
* 显示明确错误信息；
* 不让整个桌面白屏。

---

## 8.2 AppDefinition

```ts
type AppKind = "internal" | "iframe" | "external";

interface AppDefinition {
  id: string;
  name: string;
  kind: AppKind;

  icon: string;
  description?: string;

  url?: string;
  internalComponent?: string;

  defaultWidth: number;
  defaultHeight: number;
  minWidth?: number;
  minHeight?: number;

  desktop: boolean;
  pinned: boolean;

  trusted?: boolean;
}
```

## 8.3 字段规则

### `id`

* 全局唯一；
* 只允许小写字母、数字、点、短横线；
* 发布后不应随意修改；
* 作为窗口状态和持久化状态的主键。

### `kind`

`internal`：

* 必须指定 `internalComponent`；
* 不需要 `url`。

`iframe`：

* 必须指定 `url`；
* 仅用于用户信任的服务。

`external`：

* 必须指定 `url`；
* 使用新标签页打开；
* 不创建任务栏窗口。

### `desktop`

决定是否显示桌面快捷方式。

### `pinned`

决定首次运行时是否固定到任务栏。

用户之后的固定状态优先于配置默认值。

# 9. 桌面需求

## 9.1 桌面容器

桌面占满浏览器视口：

```css
html,
body,
#root {
  width: 100%;
  height: 100%;
  margin: 0;
  overflow: hidden;
}
```

结构：

```text
DesktopRoot
├── WallpaperLayer
├── DesktopIconLayer
├── WindowLayer
├── AppMenuLayer
└── Taskbar
```

层级顺序必须固定。

---

## 9.2 桌面图标

第一版桌面图标使用固定网格，不支持自由拖动。

排列规则：

* 从左上角开始；
* 从上到下排列；
* 一列放满后进入下一列；
* 图标大小一致；
* 名称最多显示两行；
* 超出部分省略。

交互：

* 单击：选中；
* 双击：打开；
* 点击桌面空白：取消选中；
* 键盘 Enter：打开当前选中图标；
* 不实现右键菜单。

桌面图标来源：

```ts
apps.filter(app => app.desktop);
```

---

## 9.3 壁纸

第一版支持：

* 一个默认壁纸；
* 配置文件指定壁纸 URL；
* 设置应用中填写壁纸 URL；
* 恢复默认壁纸。

不实现：

* 文件上传；
* 壁纸市场；
* 动态壁纸；
* 视频壁纸；
* 自动轮换。

壁纸使用：

```css
background-size: cover;
background-position: center;
background-repeat: no-repeat;
```

# 10. App 菜单需求

App 菜单包含：

* 搜索输入框；
* 全部应用列表；
* 应用图标；
* 应用名称。

搜索规则：

* 不区分大小写；
* 匹配应用名称；
* 匹配应用 ID；
* 输入为空时显示所有应用；
* 暂不实现拼音和模糊搜索。

排序：

1. 固定应用；
2. 其他应用按名称排序。

菜单行为：

* 点击开始按钮切换打开和关闭；
* 点击菜单外部关闭；
* Escape 关闭；
* 启动应用后关闭；
* 菜单打开后搜索框自动获得焦点。

# 11. 任务栏需求

任务栏结构：

```text
[App 菜单] [固定应用和运行应用]              [时间]
```

## 11.1 应用项目生成规则

任务栏显示：

* 用户固定的应用；
* 当前正在运行但未固定的应用。

同一个应用只显示一个项目。

## 11.2 状态

任务栏应用项目必须区分：

* 未运行；
* 正在运行；
* 当前活动；
* 已隐藏。

建议通过下划线、背景或圆点表达，不要求复杂动画。

## 11.3 点击行为

未运行：

* 启动应用。

已运行且隐藏：

* 显示并聚焦。

已运行、可见但不是活动窗口：

* 聚焦。

已运行并且是活动窗口：

* 隐藏。

## 11.4 右键菜单

第一版只需支持两个操作：

* 固定到任务栏／从任务栏取消固定；
* 关闭应用。

未运行应用只显示固定操作。

不实现跳转列表和最近文件。

## 11.5 时间

显示：

* 小时；
* 分钟。

每分钟更新一次。

不显示秒。

---

# 12. 窗口需求

## 12.1 默认尺寸

创建窗口时：

1. 优先使用保存的尺寸和坐标；
2. 没有保存状态时使用应用默认尺寸；
3. 默认出现在桌面可用区域中央；
4. 多个新窗口可以略微错开；
5. 窗口不得覆盖任务栏。

## 12.2 可用区域

窗口可用区域：

```text
顶部：0
左侧：0
右侧：0
底部：任务栏高度
```

假设任务栏高度为 48px，则 WinBox 创建时设置：

```ts
bottom: 48
```

实际实现应从 CSS 变量或常量读取，避免重复写死。

## 12.3 窗口关闭

关闭窗口后：

* 对应应用从运行中列表删除；
* 任务栏运行标记消失；
* 保存最后位置和尺寸；
* 不再在刷新后自动恢复，除非用户关闭前它属于上次会话恢复流程之外的特殊状态。

简单规则：

> 用户明确关闭的应用，刷新后不恢复；仅刷新前仍然打开的应用才恢复。

## 12.4 页面刷新恢复

页面加载后：

1. 加载应用配置；
2. 加载持久化桌面状态；
3. 校验保存的应用 ID 是否仍存在；
4. 恢复上次仍运行的应用；
5. 逐个恢复窗口；
6. 修正越界坐标；
7. 最后恢复活动窗口。

如果某个应用已经从配置中删除：

* 忽略其运行状态；
* 清理对应持久化记录；
* 不报致命错误。

# 13. iframe 应用

## 13.1 基本行为

iframe 应用内容占满窗口主体：

```css
.app-iframe {
  width: 100%;
  height: 100%;
  border: 0;
  display: block;
}
```

## 13.2 地址规则

第一版推荐将自托管应用反向代理到同一域名：

```text
https://desktop.example.com/services/files/
https://desktop.example.com/services/transmission/
```

桌面应用运行于：

```text
https://desktop.example.com/
```

这样可以减少跨域认证和 Cookie 问题。

## 13.3 无法嵌入时的处理

某些服务可能禁止 iframe 嵌入。

如果 iframe 加载失败，浏览器未必会提供可可靠捕获的错误事件，因此第一版需要在窗口工具区提供：

> 在新标签页打开

每个 iframe 应用都应能随时在新标签页打开其 URL。

配置中的 `external` 类型则始终直接新开标签页。

## 13.4 安全边界

V0.1 只允许管理员在配置文件中添加 iframe 应用。

不允许普通页面输入任意 URL 并创建 iframe。

第一版不建立复杂权限系统。

# 15. 状态模型

## 15.1 AppState

```ts
interface AppState {
  apps: Record<string, AppDefinition>;
  configStatus: "loading" | "ready" | "error";
  configError?: string;
}
```

## 15.2 WindowState

```ts
type WindowDisplayState =
  | "normal"
  | "maximized"
  | "hidden";

interface WindowState {
  appId: string;

  displayState: WindowDisplayState;
  active: boolean;

  x: number;
  y: number;
  width: number;
  height: number;

  openedAt: number;
}
```

因为一个应用只有一个窗口，`appId` 可以直接作为窗口 ID。

## 15.3 DesktopPreferences

```ts
interface DesktopPreferences {
  wallpaper: string;
  pinnedAppIds: string[];
  selectedDesktopAppId: string | null;
}
```

`selectedDesktopAppId` 不需要持久化。

## 15.4 PersistedDesktopState

```ts
interface PersistedDesktopState {
  schemaVersion: 1;

  wallpaper: string;
  pinnedAppIds: string[];

  runningAppIds: string[];
  activeAppId: string | null;

  windows: Record<string, {
    displayState: WindowDisplayState;
    x: number;
    y: number;
    width: number;
    height: number;
  }>;
}
```

必须保留 `schemaVersion`，但第一版不需要实现复杂迁移系统。

遇到无法识别的数据版本时：

* 忽略旧状态；
* 恢复默认值；
* 不让应用崩溃。

```ts
interface DesktopActions {
```

* AppRuntimeManager；
* CapabilityManager；

* DependencyInjectionContainer。

第一版普通函数和一个 Zustand store 足够。

# 17. 错误处理

必须处理：

## 配置文件错误

包括：

* 请求失败；
* JSON 格式错误；
* 应用 ID 重复；
* 必填字段缺失；
* 未知应用类型。

处理方式：

* 有效应用继续加载；
* 无效应用跳过；
* 设置应用中显示错误；
* 控制台输出具体信息；
* 桌面不能整体崩溃。

## 图标加载失败

显示统一的默认应用图标。

## iframe URL 缺失

应用标记为不可启动，并显示错误提示。

## localStorage 数据损坏

清除损坏状态并恢复默认状态。

## React 应用异常

为内建应用增加 Error Boundary。

某个应用异常不能导致任务栏和桌面消失。

# 22. 性能要求

第一版目标：

* 普通桌面电脑上首次加载后交互无明显停顿；
* 同时打开五个 iframe 窗口时，桌面操作仍可正常响应；

* 隐藏窗口时不销毁 iframe；
* 关闭窗口时销毁 iframe 和 React Root。

不设置不可靠的毫秒级硬指标。
