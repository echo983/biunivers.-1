# 浏览器云端个人桌面 V0.14 Registry、Image 与持久 Schema 规范评审

状态：评审通过，可施工

日期：2026-07-31

评审对象：《浏览器云端个人桌面 V0.14 Registry、Image 与持久 Schema 局部设计》

## 1. 结论

设计在 V0.14-A 范围内逻辑闭环，可以施工。它回答了应用身份从哪里来、tag 如何固定为
不可变版本、Application 与 Workspace 如何原子关联、secret 如何避免进入普通配置，以及
Runtime 与 Manager 的权限边界。

## 2. 必要性审查

保留项均为第一条 BWA 安装闭环所必需：

- repository 长期身份与 digest 安装版本分离；
- Runtime 内执行 pull/inspect，Manager 不持有 Docker socket；
- Application/Instance/Workspace 同库约束；
- default Instance 确定普通打开语义；
- 普通变量和敏感变量分离；
- Schema 迁移、备份与稳定错误；
- 已绑定 Workspace 删除保护。

若删除其中任何一项，会分别产生可变 tag 竞态、权限扩散、孤儿绑定、打开歧义、secret
泄露或数据删除风险。

## 3. 已主动删减

本阶段不实现或冻结：

- 私有 registry 登录和凭据；
- 完整 OCI Distribution 客户端；
- 多架构调度和平台选择；
- 应用配置 Schema；
- 多容器和 Compose；
- 外部 Vault、加密密钥轮换和硬件密钥；
- 自动更新、周期检查和镜像 GC；
- Instance 级不同 digest；
- 生命周期 observed state、代理和 iframe；
- 从已有 Workspace Fork/选择集派生的全部 UI。

这些能力不会阻塞“安装、注册、创建空白状态并跨重启保持”的第一闭环。

## 4. 自洽性检查

### 4.1 应用身份

tag 只用于发现，Runtime 在 pull 后从本地实际 RepoDigest 固定版本，避免解析和拉取之间的
竞态。repository 是 Application 主键，因此更新 digest 不制造第二个应用身份。

### 4.2 状态所有权

Instance 与 Workspace 的独占外键位于同一 SQLite，default Instance 使用延迟外键，首次
创建可以在一个事务内闭环。Container 和本地 image ID 没有进入持久模型。

### 4.3 WORM 与事务

空白 Workspace 的不可变对象可以先写后发布；事务失败只留下不可达对象，符合现有 GC
模型。Ref、Workspace 与 Instance 的可达关系则在单一 SQLite 事务中发布。

### 4.4 Secret

第一版没有虚构 SQLite 与独立文件之间的跨介质原子事务。规定的写入顺序使故障退化为
可清理孤儿，并对缺值失败关闭。安全承诺与概念设计一致，不宣称抵抗宿主数据目录泄露。

## 5. 风险和施工门禁

主要风险不是 Schema 本身，而是 Docker inspect 输出解析和迁移兼容：

- 必须使用参数数组调用 Docker，禁止 shell 拼接；
- 必须按 canonical repository 筛选 RepoDigest；
- 必须限制 inspect 输出和 labels 大小；
- v2→v3 迁移测试必须同时覆盖成功、回滚和备份恢复；
- `deleteWorkspace` 必须把绑定冲突翻译为稳定业务错误；
- secret 测试必须直接检查 SQLite 字节中不存在测试值。

未通过上述门禁时，不接入管理 UI，也不开始 Lifecycle。

## 6. 最终判断

V0.14-A 没有引入新的应用类型、权限语言或编排系统。新增结构是把已经冻结的 BWA 概念
落实为最小持久模型和窄 Image 能力，复杂度与数据安全风险相称，适合作为下一施工切片。
